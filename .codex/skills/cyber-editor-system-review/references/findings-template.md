# Findings Template

Use this structure for system reviews.

## Findings

1. `severity` short title
   - Why this matters
   - Doc evidence
   - Code evidence
   - Test evidence or missing-test evidence
   - Consequence
   - Required correction direction

Repeat for each finding, ordered by severity.

## Open Questions / Assumptions

- List only issues that materially affect the judgment.

## Overall Assessment

- Docs sufficient for product alignment: yes / no / partial
- Code boundaries healthy enough for extension: yes / no / partial
- Safe for broad continued development: yes / no / conditional
- Reproduction readiness for another team or AI: percentage or qualitative band

## Immediate Next Actions

1. highest-priority repair
2. second repair
3. third repair
