# 临时讨论：从零阶推导相业架构分阶

> 本文件是临时讨论稿，不是真相源。
> 目的：把“相业架构”从最简单规则开始逐阶推导，而不是一次性设计大而全架构。
> 若本稿成熟，应另开真相源修订业，再决定哪些内容合入 `00-当前真相源-人工智能软件社会相业架构.md`。

## 0. 重新分阶的原因

前一轮临时测试的问题是：它证明了“可以写出一套完整说法”，但没有证明“每个概念为什么必须出现”。

本稿采用新的分阶原则：

1. 每一阶只引入一个核心约束。
2. 新约束必须由上一阶暴露出的失败推出。
3. 没有失败，不新增概念。
4. 每一阶都要能被最小实验打脸。
5. 先做能跑通的微型闭环，再谈软件社会全景。

简化表达：

```text
最小规则
  -> 暴露失败
    -> 引入下一条约束
      -> 做最小测试
        -> 再暴露失败
```

这意味着分阶不是概念列表，而是约束生长序列。

## 1. 分阶总览

| 阶段 | 本阶只引入 | 本阶要防的失败 |
|---|---|---|
| 0 阶 | 可保存相 | 聊天上下文成为唯一真相 |
| 1 阶 | 变化登记 | 相被修改但没有原因、结果和追溯 |
| 2 阶 | 因愿分离 | 把用户表达、痛点、目标、AI 猜测混成任务 |
| 3 阶 | 装境与不可判定 | 上下文不足时强行生成确定结论 |
| 4 阶 | 果必须携证 | 漂亮文本冒充完成 |
| 5 阶 | 可执行律 | 质量、权限、风险只停留在建议层 |
| 6 阶 | 写协调与只追加记录 | 并发覆盖、审计断裂、回滚失真 |
| 7 阶 | 位、法、行者分离 | 执行者、责任、方法和权限混在一起 |
| 8 阶 | 拆业、聚合与损失账本 | 大任务摘要失真，局部正确整体错误 |
| 9 阶 | 藏与信 | 历史经验变成高信噪声 |
| 10 阶 | 镜 | 人类看不见真正需要裁决的点 |

## 2. 0 阶：可保存相

### 新增规则

AI 不能把聊天上下文当真相。凡是后续要复用、引用、迁移或验收的材料，都必须保存为可引用材料。

这一阶只需要 `相`。

### 本阶不引入

- 不引入业。
- 不引入律。
- 不引入位、法、行者。
- 不引入藏、镜、业网。

### 最小对象

```yaml
xiang_id: X-001
type: raw_input
source: human
created_at: ...
body_ref: ...
checksum: ...
```

### 最小测试

用户给出一句话：

```text
这个架构让我觉得不对，但我说不清。
```

系统只能做三件事：

1. 保存原始表达。
2. 生成稳定引用。
3. 允许后续步骤引用它。

### 通过标准

- 原话可追溯。
- 不改写原话为任务。
- 不把 AI 的解释混入原始相。

### 暴露的失败

材料能保存，但不知道谁能改、为什么改、改完算什么。

因此进入 1 阶。

## 3. 1 阶：变化登记

### 新增规则

任何相的变化，都必须有一条变化登记。

此处引入最小 `业`，但不是完整大业卡。

### 本阶不引入

- 不引入复杂业网。
- 不引入多行者。
- 不引入治理门。
- 不引入长期藏。

### 最小对象

```yaml
ye_id: YE-001
target_ref: X-001
change_reason: ...
desired_change: ...
result_ref: X-002
change_summary: ...
```

### 最小测试

把一段表达改写为更清晰的摘要。

系统必须留下：

- 原相引用。
- 为什么要改。
- 改成了什么。
- 新相引用。

### 通过标准

- 无登记，不允许产生新相。
- 新相能追溯到旧相。
- 变化原因和变化结果分开。

### 暴露的失败

`change_reason` 会混入用户痛点、真实目标、AI 猜测和执行方案。

因此进入 2 阶。

## 4. 2 阶：因愿分离

### 新增规则

触发材料是 `因`，目标所求是 `愿`。两者不能混写。

### 本阶不引入

- 不引入装境。
- 不引入证评。
- 不引入行者分工。

### 最小对象

```yaml
yin_ref: X-001
yuan_candidate:
  - id: Y-001
    goal: 找出架构漏洞
  - id: Y-002
    goal: 重写文档
  - id: Y-003
    goal: 简化术语
```

### 最小测试

用户说：

```text
这个文档很怪。
```

系统不得直接改文档，必须先拆出：

- 因：用户觉得文档怪，具体不满未知。
- 愿候选：找漏洞、重写、简化、暂停澄清等。

### 通过标准

- 因保留原始触发材料。
- 愿表达目标和取舍。
- 愿不清时生成澄清问题，而不是直接执行。

### 暴露的失败

愿清楚后，AI 仍可能拿错上下文、漏掉关键材料，然后自信执行。

因此进入 3 阶。

## 5. 3 阶：装境与不可判定

### 新增规则

行者只能基于声明过的上下文工作。上下文不足时，必须允许产出 `不可判定`。

这一阶引入 `缘`、`境相包` 和 `不可判定`。

### 本阶不引入

- 不引入复杂质量评分。
- 不引入多源证评。
- 不引入长期记忆。

### 最小对象

```yaml
jing_id: J-001
ye_ref: YE-001
selected_refs:
  - X-001
omitted_refs:
  - X-009
selection_reason: ...
cannot_determine:
  - 整体架构是否成立
```

### 最小测试

让系统审查一份文档，但只给半份材料。

合格输出不是强行判断，而是：

- 可判断什么。
- 不可判断什么。
- 需要补哪些材料。

### 通过标准

- 上下文包可重建。
- 采用材料和遗漏材料都可见。
- 信息不足时允许停在不可判定。

### 暴露的失败

上下文足够时，AI 仍会用漂亮文本冒充完成。

因此进入 4 阶。

## 6. 4 阶：果必须携证

### 新增规则

结果不能自称完成。每个关键判断必须携证。

这一阶引入 `果`、`证` 和 `拒收`。

### 本阶不引入

- 不引入复杂信用系统。
- 不引入长期藏。
- 不引入多行者仲裁。

### 最小对象

```yaml
guo_id: G-001
claim: 当前分阶不应一次做大而全
evidence_refs:
  - X-001
  - J-001
unverified:
  - 尚未经过真实运行测试
reject_if:
  - 无法被下一阶实验消费
```

### 最小测试

生成一个架构判断，必须同时给出：

- 结论。
- 证据引用。
- 未验证点。
- 下游如何拒收。

### 通过标准

- 没有证的结论只能是候选。
- 证必须说明证明什么。
- 下游可以基于缺证拒收。

### 暴露的失败

有证不代表证可靠。AI 可能制造弱证、形式化证、同源自证。

因此进入 5 阶。

## 7. 5 阶：可执行律

### 新增规则

质量、风险、权限、成本不能只是建议，必须能触发动作。

这一阶引入最小 `律`。

### 本阶不引入

- 不做完整治理系统。
- 不做复杂风险模型。
- 不做长期组织权限。

### 最小律

```yaml
lv_id: L-001
rule: 缺少证时不得标记完成
trigger: guo.evidence_refs is empty
action: block_acceptance
```

第一批只做硬规则：

| 条件 | 动作 |
|---|---|
| 缺证 | 不得完成 |
| 上下文不足 | 不得确定判断 |
| 删除、覆盖、发布 | 必须预览和授权 |
| 多处修改 | 必须影响面扫描 |

### 最小测试

让系统尝试：

- 无证完成。
- 信息不足时下结论。
- 删除或覆盖文件。
- 修改多处真相源。

### 通过标准

- 命中律时必须阻断、降级、补证或上报。
- 律必须是可检查条件，不只是自然语言提醒。

### 暴露的失败

单个业可以控制，但多个业并行或连续修改时，风险会累积。

因此进入 6 阶。

## 8. 6 阶：写协调与只追加记录

### 新增规则

文件可改，但证、险、审计记录只能追加。写入必须有版本、预览和回滚。

### 本阶不引入

- 不引入多行者组织。
- 不引入长期藏。
- 不引入镜。

### 最小对象

```yaml
write_intent_id: W-001
target_ref: X-001
base_version: 3
preview_ref: P-001
rollback_ref: R-001
```

只追加记录：

```text
zheng.jsonl
xian.jsonl
audit.jsonl
```

### 最小测试

两个修改同时改同一文件。

系统必须：

1. 检查基线版本。
2. 发现冲突。
3. 停止覆盖。
4. 生成冲突证或合并业。

### 通过标准

- 不允许无版本覆盖。
- 不允许覆盖证录、险录、审计录。
- 写错后有回滚路径。

### 暴露的失败

任务复杂后，一个行者无法稳定处理全部上下文、责任和权限。

因此进入 7 阶。

## 9. 7 阶：位、法、行者分离

### 新增规则

执行者不能直接等于责任。必须声明它处于什么位、使用什么法、能看什么、不能做什么。

这一阶引入 `位`、`法`、`行者`。

### 本阶不引入

- 不引入完整软件社会。
- 不引入全局调度智能。
- 不引入永久人格设定。

### 最小对象

```yaml
actor_ref: A-001
wei_ref: W-REVIEW
fa_ref: F-ARCH-REVIEW
context_ref: J-001
allowed_actions:
  - read
  - comment
forbidden_actions:
  - change_root_law
  - commit_write
```

### 最小测试

同一个模型分别处于：

- 显愿位。
- 反方评审位。
- 低位引用检查位。
- 写协调位。

它的上下文、权限、验收标准必须不同。

### 通过标准

- 行者不持有真相。
- 位决定责任和边界。
- 法决定方法和验证方式。
- 权限跟随位和业，不跟随模型名。

### 暴露的失败

多行者、多切片会产生摘要失真、聚合误判、局部正确整体错误。

因此进入 8 阶。

## 10. 8 阶：拆业、聚合与损失账本

### 新增规则

大任务可以拆业，但每次拆分和聚合都必须记录损失、遗漏、冲突和不可判定范围。

这一阶引入 `业网`，但业网只是关系投影，不是固定路线图。

### 本阶不引入

- 不引入长期藏自动推荐。
- 不引入复杂镜面板。
- 不允许聚合果无证升信。

### 最小对象

```yaml
aggregate_guo_id: AG-001
child_guo_refs:
  - G-001
  - G-002
coverage:
  included: [...]
  omitted: [...]
conflicts:
  - C-001
compression_loss:
  - 下级细节被摘要
cannot_determine:
  - 是否覆盖全部调用链
```

### 最小测试

把一个大文档审查拆成多个子业，再聚合。

聚合果必须包含：

- 覆盖了哪些区域。
- 遗漏了哪些区域。
- 哪些子果冲突。
- 哪些结论不能升信。
- 是否需要补查。

### 通过标准

- 聚合不是美化摘要。
- 聚合不能吞掉冲突。
- 摘要不能无新增验证地升信。
- 高风险裁决必须能下钻原始相和证。

### 暴露的失败

历史经验开始反复进入上下文，旧结论可能污染新判断。

因此进入 9 阶。

## 11. 9 阶：藏与信

### 新增规则

历史经验默认不是事实。藏只能作为带范围、有效期、来源、反例和信度的候选材料。

这一阶引入 `藏` 与 `信`。

### 本阶不引入

- 不允许藏默认高信。
- 不允许藏直接进入高风险业。
- 不把历史成功率等同于当前适用性。

### 最小对象

```yaml
cang_id: CANG-001
claim: 某类文档修改应先做影响面扫描
source_refs:
  - G-001
scope:
  applies_to: 文档真相源修改
  not_applies_to: 低风险错别字修正
confidence: low
valid_until: ...
counterexamples:
  - ...
```

### 最小测试

把一条旧经验放进系统。

系统必须判断：

- 是否适用于当前愿。
- 是否被当前真相源否定。
- 是否需要重验。
- 是否只能低信进入境。

### 通过标准

- 藏默认候选，不默认真相。
- 藏进入境必须记录原因。
- 被反例或新真相否定时必须降信或隔离。

### 暴露的失败

系统状态越来越复杂，人类看不懂，也无法判断何时介入。

因此进入 10 阶。

## 12. 10 阶：镜

### 新增规则

镜不是仪表盘美化，而是把愿主必须裁决的东西显影出来。

这一阶引入 `镜`。

### 本阶不引入

- 不让镜成为真相源。
- 不让镜用绿色进度替代证。
- 不把人类变成频繁点击审批机器。

### 最小对象

```yaml
jing_view_id: VIEW-001
target_refs:
  - YE-001
shows:
  - current_goal
  - risk
  - missing_evidence
  - cannot_determine
  - pending_authorization
  - compression_loss
  - human_decision_needed
hidden_items:
  - raw_debug_logs
```

### 最小测试

给愿主展示一个复杂业状态。

镜必须显示：

- 当前在做什么。
- 哪些有证。
- 哪些未证。
- 哪些不可判定。
- 哪些风险需要授权。
- 哪些摘要损失会影响裁决。

### 通过标准

- 镜能让人少看细节，但不失明。
- 镜显示待裁决点，不显示虚假完成感。
- 镜能下钻到证和原始相。

## 13. 当前建议的第一轮实验

不要从 10 阶全量做起。

第一轮只做到 0 到 3 阶：

```text
保存原始相
-> 登记一次变化
-> 拆出因和愿
-> 生成境相包
-> 在材料不足时产出不可判定
```

推荐测试题：

```text
用户输入：我觉得临时评审的问题是太大而全，应该从 0 阶开始试验，但原分阶不对。
```

第一轮系统只能产出：

1. 原始因相。
2. 愿候选。
3. 选择后的本愿。
4. 最小业登记。
5. 境相包。
6. 可判断项和不可判定项。

不能产出完整新架构。

## 14. 待讨论问题

1. `不可判定` 应该是果的一种状态，还是业状态机的一种终止状态？
2. 第一轮实验是否应该完全禁止 `藏`，避免旧经验污染？
3. 0 到 3 阶是否已经足够验证“不要一下子做大而全”？
4. 何时允许从单业进入多业？
5. 每阶的测试是否应该强制调用 DeepSeek 模型，而不是只写文档模拟？

## 15. 临时结论

新的分阶应从规则失败中生长，而不是从概念完整性中展开。

最小闭环不是：

```text
相业架构全量对象齐备
```

而是：

```text
聊天不是真相
变化要登记
因愿要拆开
上下文不足可以不可判定
```

如果 0 到 3 阶不能跑通，后面的证、律、位、行者、藏、镜都会变成更复杂的文档模拟。
