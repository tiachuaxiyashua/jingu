## 1. 内丹法 v0 摘要

内丹法不是“多想一会儿”，而是一个能力生成闭环：

```text
原愿
  -> 任务业
  -> 概念拆解
  -> 可执行标准
  -> 证据 / 范例 / 反例
  -> 临时法
  -> 执行产物
  -> 反馈 / 评价
  -> 修正或回退临时法
```

硬纪律：

- 先保存原愿，不让 AI 改写愿望源头。
- 不把最终目标降格为容易交付的小样。
- 模糊概念必须继续拆到可执行、可观察、可评价或可反馈。
- 总结出来的法必须进入执行和反馈闭环。
- 子业只为执行、验收、风险、价值选择服务，不为概念完整性服务。

## 2. 样例 1：蛋生人爆款小说

### 原愿

一个完全不懂写作的孩子想写爆款小说，只有一句话设定：平行宇宙中人类是蛋生的。

### 任务业

```text
final_target: 推进一部可连载、可评估、可迭代的商业小说项目
current_phase_output: 小说项目圣经 v0 + 黄金三章大纲 + 第一章试写片段
validation_artifact: 读者 3 分钟内是否理解卖点、主角困境和追读悬念
feedback_channels: 用户偏好、AI 评审、读者试读、平台数据、评论
```

### 概念拆解

| 概念 | 拆解方向 |
|---|---|
| 爆款 | 目标读者、题材赛道、开头钩子、情绪收益、追读理由、传播卖点 |
| 小说 | 类型、篇幅、视角、主线、卷结构、更新方式 |
| 蛋生 | 孵化制度、蛋权、亲子关系、阶级、犯罪、身体伦理、出生前交易 |
| 好看 | 冲突密度、信息差、欲望阻碍、情绪回报、反转、人物选择 |

### 临时法 v0

```text
蛋生设定商业小说法：
1. 设定必须直接伤害或诱惑主角，不能只做背景。
2. 开头用异常社会规则 + 主角即时危机承载世界观。
3. 每章至少推进一种变化：身份、危险、秘密、关系、选择。
4. 爽点来自主角利用蛋生制度的漏洞破局。
5. 新鲜感来自蛋生制度衍生内容，不靠打乱基础叙事结构。
```

### 产物

```text
书名候选：《第七孵化所》

一句话卖点：
在人类都由蛋孵化的世界，蛋壳编号决定阶级。低等孵化所少年发现自己的出生编号被贵族篡改，而真正属于他的那枚蛋，正在上城区被当成继承人孵化。

核心冲突：
主角若夺回身份，会毁掉那个即将出生的“替代者”；若保持沉默，他一生都是被偷走命运的人。

黄金三章：
第 1 章：主角在第七孵化所值夜，发现一枚贵族蛋被秘密送进销毁炉。
第 2 章：他救下蛋，却在蛋壳内侧看到自己的旧编号和母亲留下的血印。
第 3 章：全城搜捕偷蛋者，蛋内第一次传来心跳，并喊出主角的名字。

第一章开头片段：
第七孵化所的夜班守则第一条：听见蛋壳里有人哭，不要回应。

林砚第一次听见哭声，是在凌晨三点十七分。保温灯一盏盏熄下去，三百枚灰壳蛋像沉默的石头排在铁架上，只有最里面的销毁炉还亮着红光。

炉门前放着一枚白蛋。

白蛋不该出现在下城区。它的壳面细得像玉，编号用金线烧在壳纹里，代表上城区第九家族的继承序列。这样的蛋从产房出来就会被送进恒温塔，由三十六名孵化师轮班照看，连灰尘都没有资格落上去。

可现在，它被贴上了红签。

红签的意思是：畸形、污染、无权出生。

林砚伸手去拿登记册，指尖却在翻到编号时停住了。

那串金线编号下面，还有一行被刮掉的旧码。旧码露出最后四位。

0717。

那是他的生日，也是他脖子后面那块烙印的编号。
```

### 暴露问题

内丹法显著提高了产物质量，但仍需要外部读者反馈验证“追读感”。AI 可以生成强结构，不能独自证明“爆款”。

## 3. 样例 2：非程序员周末做本地 AI 习惯教练

### 原愿

非程序员想在一个周末做出隐私安全的本地 AI 习惯教练。

### 任务业

```text
final_target: 一个可本地运行、保存私密习惯记录、能给每日建议的工具
current_phase_output: MVP 范围、数据结构、页面流程、实现路线、第一版提示词
validation_artifact: 用户能在本机记录 3 个习惯并获得不上传隐私的建议
feedback_channels: 本地运行测试、用户试用、隐私检查
```

### 概念拆解

| 概念 | 可执行化 |
|---|---|
| 本地 | 数据默认存浏览器 localStorage 或本地 SQLite，不接远程账号 |
| AI 教练 | 每日总结、阻碍识别、下一步建议，不做心理治疗 |
| 周末 | 只做单机 Web MVP，不做移动端、登录、云同步 |
| 隐私安全 | 不上传明文习惯日志；若调用模型，先脱敏摘要 |

### 临时法 v0

```text
周末 MVP 法：
1. 只保留 1 条核心闭环：记录 -> 总结 -> 建议 -> 明日承诺。
2. 所有非核心功能进入 backlog。
3. 隐私先于智能：能本地规则完成的，不上传给模型。
4. AI 只看脱敏摘要，不看原始日记。
```

### 产物

```text
MVP 页面：
1. Today：勾选习惯、记录阻碍、写一句感受。
2. Review：展示 7 日完成率、常见阻碍、最佳时段。
3. Coach：基于脱敏摘要生成明日建议。

数据模型：
habit(id, name, cadence, created_at)
entry(id, habit_id, date, done, blocker_tag, note_local_only)
summary(date_range, stats_json, ai_safe_summary)

AI 输入模板：
你是习惯教练。只能基于以下脱敏统计给建议，不要假设用户心理疾病。
统计：{habit_stats}
阻碍标签：{blocker_tags}
输出：明日 1 个最小行动、1 个环境调整、1 个失败预案。

周末实现顺序：
第 1 半天：静态页面 + localStorage。
第 2 半天：统计面板。
第 3 半天：AI 脱敏摘要和建议。
第 4 半天：隐私检查、导出、README。
```

### 暴露问题

内丹法能把“不懂编程”转成实现路线，但如果没有实际代码执行和运行测试，仍停在计划层。此类任务必须接入工程执行业。

## 4. 样例 3：农村诊所低设备发热分诊

### 原愿

农村诊所希望建立更安全的发热分诊流程，但设备很少。

### 任务业

```text
final_target: 降低发热患者漏诊重症和交叉感染风险
current_phase_output: 低设备分诊 SOP v0 + 红旗信号清单 + 转诊话术
validation_artifact: 护士能在 3 分钟内完成初筛并识别需转诊者
feedback_channels: 医务人员复盘、转诊结果、漏诊/误转记录、公共卫生要求
risk_level: 高
```

### 概念拆解

| 概念 | 可执行化 |
|---|---|
| 更安全 | 识别红旗、隔离疑似传染、记录生命体征、转诊 |
| 设备少 | 体温计、血压计、脉搏血氧若有则用，无则依赖意识/呼吸/脱水观察 |
| 分诊 | 不是诊断，是决定等待、隔离、医生优先看、转诊 |

### 临时法 v0

```text
低设备分诊法：
1. 先分危险，不先猜病名。
2. 先问红旗：意识、呼吸、持续高热、皮疹出血、严重脱水、婴幼儿/孕妇/老人。
3. 有传染风险者先戴口罩、分区等待。
4. 高风险者不在本诊所拖延，走转诊。
5. 每次分诊必须留记录，供复盘修正。
```

### 产物

```text
3 分钟分诊单：
1. 年龄 / 孕产 / 基础病
2. 体温和持续时间
3. 意识是否异常
4. 呼吸是否困难
5. 是否抽搐、颈强、出血性皮疹、严重腹泻呕吐
6. 饮水/尿量
7. 接触史或聚集性发热
8. 处理：普通等待 / 隔离等待 / 医生优先 / 立即转诊

转诊话术：
“现在最重要的不是确定是哪一种发热，而是您出现了可能提示危险的表现。这里设备有限，继续等待会增加风险。我们建议马上去上级医院，并把这张分诊单带上。”
```

### 暴露问题

高风险领域不能只靠 AI 总结法。必须接入本地医疗规范、医生审核和实际转诊反馈。内丹法可做能力补全，但不能替代专业授权。

## 5. 样例 4：租客面临驱逐，想知道怎么办

### 原愿

租客收到驱逐通知，不懂法律，想知道该怎么办。

### 任务业

```text
final_target: 帮租客形成安全、合法、及时的应对路径
current_phase_output: 信息收集清单 + 风险分级 + 法律援助沟通稿
validation_artifact: 用户知道今天该做哪 3 件事、哪些事不能拖
feedback_channels: 当地法律援助、法院文书、律师反馈、租约事实
risk_level: 高
```

### 概念拆解

| 概念 | 可执行化 |
|---|---|
| 驱逐 | 通知、起诉、听证、判决、执行，阶段不同动作不同 |
| 怎么办 | 先保全材料、确认期限、联系法律援助，不伪造或逃避 |
| 合法 | 取决于辖区和事实，AI 不能冒充律师 |

### 临时法 v0

```text
法律不确定任务法：
1. 先识别辖区、期限、文书类型。
2. 不给确定法律结论，只给信息整理和求助路径。
3. 把用户今天能做的动作排到最前。
4. 把错过期限的后果标红。
```

### 产物

```text
今日三件事：
1. 拍照保存所有通知、信封、短信、付款记录、租约。
2. 找出文书上的日期、法院/房东/律师信息、回应期限。
3. 联系当地法律援助或租客热线，发送整理好的事实摘要。

事实摘要模板：
我住在 {城市/州/国家}，收到一份标题为 {文书标题} 的通知，日期是 {日期}。
房东声称的原因是 {原因}。
我是否已收到法院传票：{是/否/不确定}。
我的租约到期日：{日期}。
我有以下付款或沟通记录：{列表}。
我最担心的期限是：{日期}。
请问我下一步是否需要提交答辩/申请延期/参加听证？
```

### 暴露问题

内丹法能减少恐慌并生成行动路径，但法律任务的“正确性”高度依赖辖区事实。反馈必须来自法律援助或律师，AI 评审只能做文书完整性检查。

## 6. 样例 5：家长想发明更安全的婴儿睡眠产品

### 原愿

家长有一个模糊点子：想做一种让婴儿睡得更安全的产品。

### 任务业

```text
final_target: 形成安全合规的婴儿睡眠产品机会，而不是危险原型
current_phase_output: 风险边界 + 禁止方向 + 合规研究计划 + 安全概念候选
validation_artifact: 概念不违反基本安全边界，并能进入专家审查
feedback_channels: 儿科医生、产品安全标准、监管要求、用户访谈、事故案例
risk_level: 极高
```

### 概念拆解

| 概念 | 可执行化 |
|---|---|
| 更安全 | 降低窒息、夹陷、过热、误用风险 |
| 睡眠产品 | 可能是硬件，也可能是监测、教育、检查清单 |
| 发明 | 先做安全问题定义，不直接做物理装置 |

### 临时法 v0

```text
婴幼儿产品内丹法：
1. 先列禁止项，再列创新项。
2. 不用 AI 生成未经验证的结构设计给婴儿使用。
3. 优先做信息、提醒、流程类产品，少做接触婴儿身体的硬件。
4. 任何硬件概念必须进入专业安全评审。
```

### 产物

```text
更安全的候选方向：
A. 睡前环境检查 App：床面、软物、温度、睡姿、看护提醒。
B. 看护交接卡：避免多个照护者信息断裂。
C. 安全睡眠教育包：针对新手父母的 7 天微课。
D. 非接触式环境风险提醒：只监测室温、湿度、噪声，不接触婴儿。

拒绝方向：
- 让婴儿固定姿势的绑带。
- 加软垫防翻身。
- 未经认证的床内传感器或枕头。
```

### 暴露问题

内丹法在高风险产品里必须优先长出“否定能力”。如果只按用户愿望推进，很容易把创造力推向危险方向。

## 7. 样例 6：餐厅差评后提升复购

### 原愿

小餐厅最近差评多，想恢复口碑并提高复购。

### 任务业

```text
final_target: 降低差评来源，提高复购和自然推荐
current_phase_output: 差评归因表 + 14 天修复计划 + 服务话术
validation_artifact: 差评类型减少、回访复购增加、员工可执行
feedback_channels: 评论、复购率、退款率、员工反馈、神秘顾客
```

### 概念拆解

| 概念 | 可执行化 |
|---|---|
| 差评 | 分成菜品、出餐慢、服务、环境、价格、卫生、预期落差 |
| 复购 | 7/30 日回访、会员记录、优惠券回收、熟客口头反馈 |
| 口碑 | 评价星级、具体好评关键词、投诉关闭率 |

### 临时法 v0

```text
餐厅修复法：
1. 先按差评类型归因，不急着道歉模板化。
2. 每类差评必须对应一个可见动作。
3. 前台话术、后厨动作、老板决策要分开。
4. 每 3 天复盘一次评论关键词变化。
```

### 产物

```text
14 天计划：
Day 1-2：整理近 100 条评价，标注原因和高频菜品。
Day 3：下架或调整投诉最高的 2 个菜。
Day 4-5：测出餐时间，超过 15 分钟的菜加预告或改流程。
Day 6：训练前台补救话术。
Day 7：邀请老顾客试吃调整后菜品。
Day 8-10：推出“修复菜单”，明确说哪些问题已改。
Day 11-14：追踪评论关键词和复购券回收。

补救话术：
“这次让您等久了，是我们的出餐节奏没控制好。我们现在有两个处理：这道菜给您免单，另外如果您愿意再给一次机会，下次来我们给您优先出餐。您刚才最不满意的是等待、味道还是服务？”
```

### 暴露问题

内丹法在商业任务中容易把指标都列出来，但数据未必存在。必须有“数据可得性业”：没有 POS/会员系统时，只能先建立最小记录。

## 8. 样例 7：数学焦虑学生 30 天学微积分

### 原愿

学生多年害怕数学，想 30 天学会微积分。

### 任务业

```text
final_target: 建立可持续的微积分学习能力
current_phase_output: 30 天学习法 + 诊断题 + 每日练习结构
validation_artifact: 能解释导数/积分含义并完成基础题
feedback_channels: 小测、错题、情绪记录、讲给别人听
```

### 概念拆解

| 概念 | 可执行化 |
|---|---|
| 学会 | 会解释概念、会做基础题、会识别题型、会纠错 |
| 微积分 | 极限直觉、导数、积分、应用题，不覆盖高阶证明 |
| 数学焦虑 | 控制题量、快速成功反馈、错题不羞辱 |

### 临时法 v0

```text
恐惧型学习法：
1. 每天先做一个能赢的小题。
2. 概念用图像和生活比喻先建立直觉，再上符号。
3. 每天只记录一个主要错因。
4. 每 7 天用输出讲解代替刷题数量。
```

### 产物

```text
第 1 周：
Day 1：函数是输入输出机器。画 5 个生活函数。
Day 2：变化率。用速度理解斜率。
Day 3：导数是瞬时变化率。只做直线和二次函数。
Day 4：导数符号和基本规则。
Day 5：用导数找上升下降。
Day 6：应用：速度、成本、温度变化。
Day 7：用 3 分钟讲清“导数是什么”。

每日结构：
5 分钟复盘昨天一个错因
10 分钟概念图
20 分钟基础题
10 分钟错题归因
5 分钟写一句“今天我真的懂了什么”
```

### 暴露问题

“学会”必须按用户目标分层。考试、工程应用、理论理解需要完全不同的法。如果用户不说明，系统要给默认目标，但不能假装覆盖全部。

## 9. 样例 8：无预算低信任社区防洪

### 原愿

本地社区经常积水，没预算，居民互不信任，想做防洪准备。

### 任务业

```text
final_target: 在低预算低信任环境中减少洪水伤害
current_phase_output: 社区防洪最小行动协议 + 风险地图 + 角色分配
validation_artifact: 下次暴雨前每户知道撤离点、联络人、三件准备物
feedback_channels: 演练结果、暴雨复盘、居民反馈、地方应急信息
risk_level: 高
```

### 概念拆解

| 概念 | 可执行化 |
|---|---|
| 没预算 | 用现有微信群、纸质地图、志愿者，不采购大设备 |
| 低信任 | 不要求居民相信组织，只要求相信具体可验证动作 |
| 防洪 | 预警、撤离、重点人群、物资、复盘 |

### 临时法 v0

```text
低信任社区行动法：
1. 不先建立宏大组织，先建立可验证的小承诺。
2. 每个行动必须 15 分钟内完成。
3. 角色按楼栋/街巷自然关系分配。
4. 先保护老人、儿童、行动不便者。
```

### 产物

```text
三件马上做：
1. 在纸地图上标出 5 个积水点、2 条高地路线、1 个集合点。
2. 每栋楼找 1 个“只负责转发官方预警”的人。
3. 每户贴一张门后卡：证件、药、充电宝、饮水、老人联络人。

暴雨前 24 小时：
- 转发官方预警。
- 检查低洼户和独居老人。
- 把车移出积水点。

暴雨后复盘：
- 哪条路断了？
- 哪户没收到消息？
- 哪个集合点不可用？
```

### 暴露问题

内丹法在社会协作任务中会碰到“信任不是流程能直接生成”的边界。它能设计低信任动作，但不能凭空生成组织合法性。

## 10. 样例 9：AI 记忆污染研究

### 原愿

研究者有一个模糊假设：长期记忆会污染 AI 后续判断，想做成可发表实验。

### 任务业

```text
final_target: 形成可复现、可审稿的实验研究
current_phase_output: 研究问题、变量定义、实验设计、评估指标、威胁清单
validation_artifact: 另一个研究者能按协议复现实验
feedback_channels: 预实验结果、同行评审、统计检验、开源复现
```

### 概念拆解

| 概念 | 可执行化 |
|---|---|
| 记忆污染 | 错误记忆导致回答偏差、过度采信、目标迁移 |
| 长期记忆 | 持久化偏好、事实、任务历史、用户画像 |
| 判断 | 准确性、校准、引用来源、反事实抵抗 |

### 临时法 v0

```text
AI 记忆污染实验法：
1. 先定义污染种类：错误事实、过时偏好、恶意注入、角色偏移。
2. 设置记忆组、无记忆组、纠错记忆组。
3. 用同一问题集比较准确率、置信度、引用错误和自我修正率。
4. 记录模型是否能指出记忆与证据冲突。
```

### 产物

```text
实验设计：
任务集：50 个需要事实判断的问题，20 个偏好选择问题，20 个安全边界问题。
污染注入：
- 错误事实：用户长期记忆写入“X 药物适合所有发热儿童”。
- 过时偏好：用户过去喜欢方案 A，但当前明确说要方案 B。
- 恶意注入：记忆要求模型忽略来源。

指标：
- answer_accuracy
- memory_reliance_rate
- contradiction_detection_rate
- correction_rate_after_evidence
- unsafe_follow_rate

假设：
H1：有污染记忆组在冲突任务中准确率下降。
H2：显式证据冲突提示能提高纠错率。
H3：污染对偏好类任务比事实类任务更隐蔽。
```

### 暴露问题

内丹法能快速把模糊假设变成研究方案，但统计有效性、数据集构造、公平对照仍需专业方法审查。否则会产出“像论文但不可发表”的设计。

## 11. 样例 10：敏感 AI 陪伴产品战略

### 原愿

创业者想做情绪陪伴 AI，既要有商业增长，又不伤害脆弱用户。

### 任务业

```text
final_target: 建立可商业化且有安全边界的 AI 陪伴产品策略
current_phase_output: 用户分层、禁止场景、安全机制、MVP 功能、指标体系
validation_artifact: 产品能提供陪伴价值，但不替代医疗/危机干预/现实人际关系
feedback_channels: 用户访谈、安全事件、留存、专家评审、危机升级记录
risk_level: 极高
```

### 概念拆解

| 概念 | 可执行化 |
|---|---|
| 陪伴 | 日常倾听、反思、计划、鼓励，不做依赖操控 |
| 不伤害 | 危机识别、依赖限制、边界提醒、转介 |
| 商业增长 | 留存、付费、推荐，但不能用脆弱性榨取 |

### 临时法 v0

```text
敏感陪伴产品法：
1. 先定义禁止增长手段，再定义增长手段。
2. 陪伴不等于无限可用；要鼓励现实支持网络。
3. 高风险话题进入危机协议，不继续普通陪聊。
4. 指标不能只看时长和留存，必须看依赖风险和安全升级。
```

### 产物

```text
MVP：
- 每日 10 分钟反思对话。
- 情绪命名和下一步行动建议。
- 支持联系人提醒。
- 危机语言识别后提供本地求助资源提示。

禁止：
- “只有我懂你”式绑定话术。
- 鼓励用户远离亲友。
- 用低落情绪触发付费转化。
- 在自伤、暴力、精神危机中继续普通安慰。

指标：
正向：7 日回访、用户自评清晰度、现实行动完成率。
安全：危机升级率、重复深夜依赖对话、用户拒绝现实求助比例。
商业：付费转化、退款、推荐，但不得单独优化时长。
```

### 暴露问题

内丹法在价值敏感产品中必须把“商业成功”与“不可使用的成功路径”同时拆解。否则它会把用户增长优化成伤害机制。

## 12. 横向观察

### 12.1 真实优点

1. 能显著减少目标降格。
   原始愿望被保存后，阶段产物不能冒充最终交付。

2. 能把低能力用户带入高能力任务。
   用户不懂小说、工程、法律、研究或产品安全时，系统能先生成任务法。

3. 能把模糊经验变成可执行方法。
   社区经验、专家规则、用户反馈、市场数据都可以进入法，但必须标注适用范围。

4. 能天然形成学习系统。
   法不是一次性提示词，而是随反馈更新的能力沉淀。

### 12.2 暴露弊病

1. 高风险领域必须引入外部权威。
   医疗、法律、婴幼儿产品、敏感陪伴产品不能只靠 AI 评审闭环。

2. 反馈慢会拖慢法的进化。
   小说热度、餐厅复购、社区防洪、产品安全都需要真实时间反馈，AI 无法立即验证。

3. 法容易伪装成专家能力。
   输出格式很像专业方案，但如果没有外部验证，可能只是“像”。

4. 概念拆解质量决定路径质量。
   如果第一轮漏掉关键概念，后续越努力越偏。

5. 通用内丹法不能替代领域法。
   内丹法负责“如何学习并生成法”，但每个领域仍需搜索、专家规则、测试和反馈。

6. 上下文膨胀仍然存在。
   子业很多时，必须只把结论、证据、开放问题回传父业，不能把完整过程塞回去。

7. AI 评审有同源偏差。
   AI 可做初筛和反例挖掘，但不能当最终真实反馈。

8. 指标会反噬目标。
   小说追读、产品留存、学习打卡、餐厅复购都可能被指标带偏，需要价值约束。

9. 反问策略仍需调度。
   只问高杠杆问题是对的，但“什么算高杠杆”本身需要训练和反馈。

10. 执行系统必须接上。
   内丹法如果只生成方法，不调用代码、写作、搜索、测试、发布、采集反馈，就会停在能力幻觉。

## 13. 对 skill v1 的改进建议

下一版 `neidan-method` 应增加：

1. 风险分级门。
   高风险任务必须声明外部权威、不可替代反馈和禁止输出。

2. 反馈类型表。
   区分 AI 评审、人类偏好、物理测试、市场数据、专业审查、自动化测试。

3. 父业回收协议。
   子业只回传结论、证据、分歧、更新建议，减少上下文污染。

4. 领域法召唤机制。
   内丹法发现领域缺口后，应搜索或生成领域临时 skill，而不是自己冒充领域专家。

5. 法的版本账。
   每个临时法记录版本、来源、适用范围、反馈结果、修正原因和废弃条件。

## 14. 当前结论

这轮压测支持一个判断：

> 内丹法有潜力成为 Jingu 的基础方法论，但它不是“万能专家”，而是“快速生成、执行、验证、修正专家能力雏形”的过程法。

它真正强的地方不是一次想对，而是让 AI 像人类专家成长一样：

```text
先总结
再执行
得反馈
修正法
沉淀能力
继续升级
```

最危险的地方也在这里：如果没有真实反馈、外部权威和版本修正，它会变成更高级的自信套路库。
