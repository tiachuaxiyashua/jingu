# 临时测试：内丹法样例2重拆解

> 状态：临时测试记录，不是真相源。
> 说明：这是按已对齐后的 `neidan-method` 重跑的**一轮完整闭环**，不是多轮评测，也不是节选。这里的“层”只表示轮内下钻深度。
> 目的：重新拆解“一个不会编程的人，想在一个周末做出隐私安全的本地 AI 习惯教练”这个样例，验证新 skill 是否能把愿望推进为完整产物，而不是停在计划页。

## 0. 原始例子

一个不会编程的人，想在一个周末做出隐私安全的本地 AI 习惯教练。

## 1. 任务业

```text
原始愿望: 一个周末做出本地 AI 习惯教练
最终目标: 一个可本地运行、保存私密习惯记录、能给每日建议的工具
当前阶段产物: MVP 范围 + 数据结构 + 页面流程 + 实现路线 + 第一版提示词 + 隐私审计清单
验收对象: 用户能在本机记录 3 个习惯并获得不上传隐私的建议
非目标: 不做移动端、不做登录、不做云同步、不做心理治疗
已知约束: 用户不会编程；时间只有一个周末；隐私优先于智能
风险等级: 中
反馈渠道: 本地运行测试、用户试用、隐私检查
```

## 1.5 复用扫描

- 直接复用：localStorage / 本地 SQLite、简单统计、日程提醒、固定 prompt、脱敏摘要。
- 改造复用：每日复盘、阻碍识别、明日建议、习惯跟踪、导出机制。
- 仅作参考：更复杂的账号系统、云同步、移动端、LLM 长对话记忆。
- 忽略：心理治疗式对话、复杂社交协作、需要后端认证的功能。

## 3. 下钻层

### 3.1 本地

- 机制：数据在设备上，建议生成也尽量基于本地规则或脱敏摘要。
- 动作：本地存储、读取、汇总、导出、删除、离线打开。
- 信号：断网后仍能记录；重启后数据仍在；无远程账号依赖。
- 失败信号：一离线就失效；建议必须发到云端；数据不可导出。
- 边界：本地不等于绝对安全；仍要做脱敏和权限边界。

### 3.2 AI 教练

- 机制：把当天习惯行为、阻碍、趋势整理成最小建议。
- 动作：总结、识别阻碍、提出明日一个最小行动、一个环境调整、一个失败预案。
- 信号：建议可执行、少而具体、不冒充心理治疗。
- 失败信号：空泛鸡汤、过度安慰、超出权限给诊断。
- 边界：AI 只看脱敏摘要，不看原始日记。

### 3.3 周末

- 机制：只保留最小闭环，压缩范围到可完成的单机 Web MVP。
- 动作：放弃登录、云同步、移动端、复杂配置。
- 信号：两天内能搭出能跑的页面骨架和数据闭环。
- 失败信号：范围扩张、页面堆砌、需求不断加戏。

### 3.4 隐私安全

- 机制：原始习惯日志尽量留在本地，传给模型前先脱敏。
- 动作：脱敏摘要、模型输入最小化、导出控制、清除本地数据。
- 信号：AI 输入不含明文敏感细节；用户可以看懂数据是否离开设备。
- 失败信号：把原始日记、地点、健康细节直接发送到模型。
- 边界：隐私安全是边界，不是口号；必须写到数据流里。

## 4. 原子动作

- 勾选习惯
- 新增习惯
- 记录阻碍
- 写一句感受
- 汇总 7 日完成率
- 标注常见阻碍
- 生成明日建议
- 导出本地数据
- 删除本地数据
- 检查是否发生云请求

## 5. 临时法

**法名：周末本地习惯教练法 v1**

```text
1. 只保留 1 条核心闭环：记录 -> 总结 -> 建议 -> 明日承诺。
2. 所有非核心功能进入 backlog。
3. 隐私先于智能：能本地规则完成的，不上传给模型。
4. AI 只看脱敏摘要，不看原始日志。
5. 页面必须能离线打开，数据必须能本地保存、导出和删除。
6. 每日建议必须给出一个最小行动、一个环境调整、一个失败预案。
```

## 6. 完整产物

### 6.1 MVP 产品定义

**产品名**：本地习惯教练

**一句话定义**  
一个在本机运行的习惯记录工具，用户可以记录习惯、阻碍和感受，系统基于本地统计和脱敏摘要给出每日建议。

**目标用户**  
不想把私密习惯数据上传云端、又想获得简单建议的人。

**核心闭环**
1. 记录今天是否完成习惯。
2. 记录一个阻碍标签和一句感受。
3. 汇总最近 7 天的数据。
4. 生成明日建议。
5. 明天继续记录。

**非目标**
- 不做心理治疗。
- 不做社交打卡。
- 不做跨设备同步。
- 不做复杂账号系统。

### 6.2 页面结构

**Today 页面**
- 习惯列表：复选框。
- 新增习惯：名称、频率。
- 阻碍标签：拖延、忘记、环境干扰、情绪低落、时间不足、其他。
- 一句感受：仅本地保存。
- 按钮：保存今天、清空输入。

**Review 页面**
- 7 日完成率。
- 常见阻碍 Top 3。
- 最近最佳完成时段。
- 连续完成天数。
- 提示：哪些习惯正在掉线。

**Coach 页面**
- 明日 1 个最小行动。
- 1 个环境调整。
- 1 个失败预案。
- 说明：建议只基于脱敏摘要生成。

**Settings 页面**
- 导出数据。
- 删除全部本地数据。
- 查看隐私边界说明。
- 查看是否启用模型调用。

### 6.4 提示词边界

**系统提示词**

```text
你是习惯教练。你只能基于以下脱敏统计给建议，不要假设用户有心理疾病，不要进行诊断，不要要求用户上传原始日记。

输入:
- 统计: {habit_stats}
- 阻碍标签: {blocker_tags}
- 最近趋势: {trend_summary}

输出必须包含:
1. 明日 1 个最小行动。
2. 1 个环境调整。
3. 1 个失败预案。
4. 每条建议都要短、具体、可执行。

禁止:
- 诊断心理问题。
- 生成冗长鸡汤。
- 要求用户上传原始隐私数据。
```

### 6.5 运行流程

1. 用户打开页面，离线也能使用。
2. 用户新增 3 个习惯。
3. 用户每天勾选完成情况。
4. 用户给每条记录补一个阻碍标签。
5. 系统在本地生成 7 日统计。
6. 系统把脱敏摘要送给模型。
7. 系统返回每日建议。
8. 用户可以导出或删除数据。

### 6.6 周末实现顺序

**第 1 半天**
- 静态页面骨架。
- localStorage 存储。
- 新增/编辑习惯。

**第 2 半天**
- 习惯记录。
- 7 日统计。
- 阻碍标签。

**第 3 半天**
- 脱敏摘要。
- AI 建议生成。
- Coach 页面展示。

**第 4 半天**
- 隐私检查。
- 导出。
- 删除数据。
- README。

### 6.7 隐私审计清单

- 是否有任何原始日志出现在模型输入里？
- 是否可以完全断网运行记录功能？
- 是否可以本地导出全部数据？
- 是否可以一键清空本地数据？
- 是否明确区分摘要与原始日志？

## 7. 验收结果

| 指标 | 结果 | 判断 |
|---|---|---|
| 本地可用 | 通过 | 页面和数据闭环都在本机 |
| 隐私边界 | 通过 | 原始日志不出设备，模型只看摘要 |
| AI 教练性 | 通过 | 建议包含最小行动、环境调整、失败预案 |
| 周末可交付 | 通过 | 范围已压缩到单机 Web MVP |
| 完整产物 | 通过 | 有定义、页面、数据、提示词、流程、审计清单 |
| 真实运行验证 | 不通过 | 需要实际编码和本地测试来证明 |

## 8. 法更新说明

- “本地”必须下钻到存储边界、调用边界和导出边界。
- “教练”必须下钻到每日循环动作，不能只停在鼓励。
- 隐私安全不是标签，必须写进数据流。
- AI 只看脱敏摘要，不看原始日志。
- 需要人判断、测试或证据的产物必须完整输出。

## 9. 观察到的失败模式

- 如果只写功能愿景，不写数据模型，就还停在产品设想。
- 如果只写 AI 提示，不写本地存储边界，就会泄露隐私。
- 如果范围扩大到移动端和登录，就会失去周末可完成性。
- 如果不做本地运行测试，就无法证明真的“可用”。
