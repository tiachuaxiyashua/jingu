# 身体内核与能力包软件架构方案

> 状态：当前上层软件架构方案。
>
> 本文档不做代码实现，不规定具体 UI 细节，不绑定现有 Cyber Editor 代码结构。它描述未来系统的上层软件架构、关键域模型、信息流转、运行边界和各部分详细设计。

## 0. 架构结论

本系统不应被设计成一个“什么都能做的超级应用”。

正确的软件架构应是：

```text
一个文件原生的 Body Kernel
  装载 Capability Package
  编排 Verifiable Move
  治理权限与信任
  保存 Evidence
  通过 Lens 向人类投影状态
  通过 Federation 连接其他超级个体
```

应用层能力不是内置在核心里的。

应用层能力来自能力包装配：

```text
应用结果 = Promise + Capability Assembly + Move Graph + Evidence + Lens + Human Decision
```

因此核心架构必须围绕以下问题设计：

- 如何定义“身体”。
- 如何定义“义体/能力包”。
- 如何装载、启用、禁用、升级、卸载能力包。
- 如何把复杂任务拆成可验证动作。
- 如何让大模型负责统领，小模型、工具、脚本负责原子执行。
- 如何让每个动作有权限、有证据、有恢复路径。
- 如何让 UI 只是镜头，不成为真相源。
- 如何让多个增强个体通过协议协作。

## 1. Frontier Refresh

日期：2026-05-10。

本架构参考以下官方方向，但不复制任何单一框架：

| 来源 | 对架构的影响 |
|---|---|
| OpenAI Agents / tools / handoffs / tracing / evals | Agent 不应只是 prompt；工具、handoff、trace、eval 和 guardrail 应是一等架构对象。 |
| LangGraph persistence / human-in-the-loop | 长任务必须有持久状态、interrupt、resume、checkpoint，而不是一次性聊天调用。 |
| MCP tools / resources / prompts / roots / authorization | 外部能力、资源根目录、工具边界和授权必须由 host 控制，不能由能力包自行决定。 |
| JSON Schema | 文件协议必须机器可校验，schema authority 不能只靠散文。 |
| OpenAPI | 外部 API/工具要有输入、输出、错误、安全和认证描述。 |
| SemVer | 能力包、Move、Lens、Evidence 协议必须有兼容性和破坏性变更规则。 |

架构约束：

- Host 控制 roots、权限、工具和外部资源。
- Runtime 控制 checkpoint、interrupt、resume、retry 和 evidence。
- Capability Package 只声明能力，不能直接获得权力。
- UI 不拥有业务真相，只渲染 Lens Projection。
- 所有可执行动作必须产生 Evidence。
- 所有 schema、引用、版本和迁移都必须可检查。

## 2. 设计目标与非目标

### 2.1 设计目标

1. **可装配**：能力包可以安装、组合、替换、升级、卸载。
2. **可验证**：复杂能力最终拆成可校验的 Move。
3. **可治理**：权限、信任、审批、审计、回滚是执行路径的一部分。
4. **可观察**：人类通过 Lens 看见状态、证据、风险和决策点。
5. **文件原生**：协议、状态、证据、能力包、运行记录尽量落到文件。
6. **模型分工**：大模型统领，小模型和工具执行可验证原子动作。
7. **可恢复**：长任务可中断、恢复、重试、回放。
8. **可联邦**：多个超级个体可共享能力声明、请求协作、交换证据。
9. **可演化**：系统可从 Pain Signal 生成 Mutation Proposal，但必须经授权。
10. **不假大空**：应用层案例必须能被还原成能力包组合和 Move Graph。

### 2.2 非目标

1. 不做万能助手。
2. 不直接内置创业、电商、论文、健康等应用助手。
3. 不把 prompt 文件夹当能力包。
4. 不让 UI 成为状态源。
5. 不让模型输出直接等同证据。
6. 不允许能力包绕过权限系统。
7. 不默认联网、写文件、发消息、执行 shell。
8. 不让用户承担无限审批。
9. 不把 Step 暴露成调度单位。
10. 不要求第一版支持跨组织联邦完整落地。

## 4. 分层职责

### 4.1 Human Subject

人类不是系统里的普通用户实体，而是最高授权源。

职责：

- 提供意志、价值判断、审美判断和责任承担。
- 对高风险动作批准、拒绝或调整。
- 定义系统承诺帮助自己增强什么能力。
- 在系统显影张力后进行最终确认。

不负责：

- 提供完整精确需求。
- 处理低认知体力劳动。
- 审批每个低风险小动作。
- 手动管理所有能力包细节。

### 4.2 Human Interface Layer

这是人类与第二身体交互的表层。

组成：

- `Probe Console`：用于张力显影，不只是聊天输入框。
- `Lens Workspace`：用于切换观察镜头。
- `Decision Inbox`：集中处理需要人类裁决的问题。
- `Trust Console`：管理能力包信任等级和权限。
- `Package Workbench`：查看、安装、沙盒测试和授权能力包。

边界：

- 可以触发请求。
- 可以渲染状态。
- 可以提交人类决策。
- 不能直接改写事实状态。
- 不能绕过 Permission Kernel 执行动作。

### 4.3 Body Kernel

这是系统核心。

它不是业务应用，而是装载能力包、运行 Move、保存证据、治理权限的身体内核。

核心职责：

- 管理能力包生命周期。
- 管理 schema 和协议版本。
- 管理能力槽位。
- 管理上下文挂载。
- 管理权限和信任。
- 编排 Move Graph。
- 路由执行器。
- 持久化证据和运行状态。
- 渲染 Lens Projection。
- 生成 Pain Signal 和 Mutation Proposal。
- 处理联邦协作请求。

### 4.4 Capability Package Layer

能力包是可插拔义体。

它声明：

- 自己提供什么能力。
- 插入哪些身体槽位。
- 暴露哪些 Move。
- 需要哪些资源、工具、模型和权限。
- 输出哪些 Evidence。
- 提供哪些 Lens。
- 如何测试、升级、回滚和卸载。

能力包不拥有：

- 用户授权。
- 文件系统任意访问权。
- 网络任意访问权。
- shell 任意执行权。
- UI 状态源。
- 全局记忆写入权。

### 4.5 Runtime Layer

运行层把 Promise 转成可执行过程。

核心过程：

```text
Tension Field
  -> Promise
  -> Capability Assembly
  -> Operation Plan
  -> Move Graph
  -> Execution Records
  -> Evidence Trail
  -> Lens Projection
  -> Artifact / Decision / Mutation Proposal
```

Runtime 负责：

- checkpoint。
- retry。
- interrupt。
- resume。
- cancel。
- rollback。
- partial result。
- audit replay。

### 4.6 Executor Layer

执行器不是“智能体角色”，而是 Move 的实际执行资源。

类型：

- `LargeModelExecutor`：战略判断、综合推理、动作设计、审计。
- `MediumModelExecutor`：草拟、比较、局部评审、结构化输出。
- `SmallModelExecutor`：抽取、分类、打标签、格式化、小范围验证。
- `ToolExecutor`：运行工具、读取资源、调用 API。
- `ScriptExecutor`：执行受控脚本。
- `HumanExecutor`：价值判断、授权、审美、最终裁决。
- `FederatedExecutor`：其他超级个体或外部能力提供者。

Executor 必须被 Runtime 选择和约束，不能由能力包直接调用。

## 5. 核心架构类设计

以下是概念类，不是代码实现。

### 5.1 `BodyKernel`

职责：

- 作为所有内核服务的组合根。
- 接收来自 UI、能力包、联邦节点的请求。
- 确保所有执行都经过权限、schema、runtime、evidence。

关键属性：

```yaml
BodyKernel:
  id: string
  profile: BodyProfile
  services:
    package_loader: PackageLoader
    schema_registry: SchemaRegistry
    slot_registry: SlotRegistry
    permission_kernel: PermissionKernel
    trust_kernel: TrustKernel
    context_mount: ContextMountService
    move_runtime: MoveRuntime
    executor_router: ExecutorRouter
    evidence_store: EvidenceStore
    lens_renderer: LensRenderer
    memory_garden: MemoryGarden
    mutation_gate: MutationGate
    federation_bus: FederationBus
```

不可变规则：

- `BodyKernel` 是唯一运行入口。
- 所有 side effect 必须经过 `PermissionKernel`。
- 所有 Move 结果必须写入 `EvidenceStore`。
- UI 只能读取 `LensProjection` 或提交 `HumanDecision`。

### 5.2 `HumanSubject`

职责：

- 表示人类的授权主体。
- 记录人类带宽、决策偏好、信任偏好。

关键属性：

```yaml
HumanSubject:
  id: string
  preferences:
    decision_style: choose_from_options | freeform | approve_reject
    interruption_level: critical_only | batch | realtime
    explanation_depth: brief | normal | detailed
  authority:
    can_approve_permissions: true
    can_override_model: true
    can_revoke_package: true
```

设计重点：

- 人类不是执行器之一那么简单。
- `HumanExecutor` 只是人类参与某个 Move 的投影。
- `HumanSubject` 才是最终授权源。

### 5.3 `TensionField`

职责：

- 保存用户未完全成形的痛点、欲望、恐惧、约束、资源、野心。

关键属性：

```yaml
TensionField:
  id: string
  raw_signals:
    - user_utterance
    - observed_behavior
    - repeated_failure
    - external_constraint
  inferred_tensions:
    - pain
    - desire
    - fear
    - resource
    - constraint
    - identity_direction
  confidence:
    score: number
    weakest_point: string
  open_questions:
    - DecisionRequest
```

边界：

- 它不是需求文档。
- 它是 Promise 形成前的张力显影结果。

### 5.4 `ProbeSession`

职责：

- 通过对话、类比、反问、证据请求显影张力。

关键属性：

```yaml
ProbeSession:
  id: string
  tension_field_id: string
  probe_moves:
    - ask_clarifying_question
    - mirror_user_language
    - propose_analogy
    - test_counterfactual
    - request_example
  outputs:
    - TensionField
    - PossibilitySeed
    - DecisionRequest
```

设计重点：

- Probe 可以调用能力包，但不能直接承诺执行。
- Probe 的产物必须可被用户修正。

### 5.5 `PromiseContract`

职责：

- 表示系统与人类之间的承诺。

关键属性：

```yaml
PromiseContract:
  id: string
  human_need: string
  capability_growth:
    strengthen: string[]
    compensate: string[]
    expand: string[]
    liberate_energy_from: string[]
  system_commitments: string[]
  human_controls: string[]
  success_signals: string[]
  boundaries:
    must_not_do: string[]
    requires_approval: string[]
  status: draft | active | paused | fulfilled | cancelled
```

架构地位：

- Promise 是运行的上层契约。
- Workflow/MoveGraph 是实现 Promise 的一种计划，不是中心对象。

### 5.6 `CapabilityPackage`

职责：

- 描述一个可装载义体包。

关键属性：

```yaml
CapabilityPackage:
  id: string
  version: semver
  protocol: string
  slots: SlotId[]
  required_roots: RootRequest[]
  required_tools: ToolRequirement[]
  required_models: ModelRequirement[]
  permissions: PermissionRequestTemplate[]
  moves: MoveDefinition[]
  lenses: LensDefinition[]
  schemas: SchemaRef[]
  tests: ContractTestRef[]
  migrations: MigrationPlan[]
```

不可变规则：

- 未通过 schema 校验不能安装。
- 未通过 contract test 不能启用。
- 未获授权不能执行 side effect。
- 新版本必须声明兼容性。

### 5.7 `CapabilityInstance`

职责：

- 表示某个能力包在某个身体里的安装实例。

关键属性：

```yaml
CapabilityInstance:
  package_id: string
  package_version: string
  installed_at: timestamp
  state: installed | disabled | sandbox | enabled | quarantined | uninstalled
  granted_permissions: PermissionGrant[]
  trust_level: TrustLevel
  local_config: object
  evidence_stats:
    success_count: number
    failure_count: number
    last_audit_score: number
```

设计重点：

- Package 是静态定义。
- Instance 是本地装载状态。
- 同一 Package 可在不同身体里有不同权限和信任等级。

### 5.8 `Slot`

职责：

- 定义身体可装载的能力面。

基础槽位：

```yaml
Slot:
  id: sense | cognition | muscle | immune | memory | lens | governance | federation
  allowed_move_verbs: string[]
  allowed_side_effects: SideEffectPolicy
  max_default_trust: TrustLevel
```

设计重点：

- 槽位是架构边界，不是 UI 分类。
- 能力包声明槽位后，Permission Kernel 才知道如何限制它。

### 5.9 `CapabilityAssembly`

职责：

- 为一个 Promise 选择一组能力包，并定义它们如何协作。

关键属性：

```yaml
CapabilityAssembly:
  id: string
  promise_id: string
  packages:
    - CapabilityInstanceRef
  roles:
    orchestrator: ExecutorPolicy
    auditors: ExecutorPolicy[]
  shared_objects:
    - Observation
    - Hypothesis
    - EvidenceRef
  constraints:
    max_cost: number
    max_time: duration
    human_interruption_policy: string
```

设计重点：

- 应用不是硬编码功能。
- 应用是一次 Assembly。

### 5.10 `Operation`

职责：

- 表示比 Move 更粗的可执行阶段。

关键属性：

```yaml
Operation:
  id: string
  goal: string
  input_refs: Ref[]
  output_refs: Ref[]
  moves: MoveRef[]
  completion_criteria: Assertion[]
```

设计重点：

- Operation 不直接执行。
- Runtime 会把 Operation 展开成 Move Graph。

### 5.11 `VerifiableMove`

职责：

- 表示最小可调度、可验证动作。

关键属性：

```yaml
VerifiableMove:
  id: string
  verb: observe | scan | extract | classify | validate | compare | rank | draft | run | write | ask_human | audit
  slot: SlotId
  input_schema: SchemaRef
  output_schema: SchemaRef
  executor_policy: ExecutorPolicy
  preconditions: Assertion[]
  postconditions: Assertion[]
  side_effects: SideEffectDeclaration
  limits: MoveLimits
  evidence_requirements: EvidenceRequirement[]
  failure_policy: FailurePolicy
```

不可变规则：

- 没有 schema 的 Move 不能运行。
- 没有 side effect 声明的 Move 不能运行。
- Move 失败必须产生 Evidence。

### 5.12 `MoveGraph`

职责：

- 描述 Move 之间的依赖、并行、分支、循环控制和中断点。

关键属性：

```yaml
MoveGraph:
  id: string
  nodes:
    - MoveNode
  edges:
    - DependencyEdge
  interrupts:
    - HumanInterrupt
  retry_policy: RetryPolicy
  checkpoint_policy: CheckpointPolicy
  loop_controllers:
    - LoopController
```

图语义：

- 默认必须是 DAG。
- 循环不能用任意回边表达。
- 循环必须由 `LoopController` 表达，带最大次数、退出条件、checkpoint 和 evidence。

原因：

```text
可恢复运行需要可计算边界。
任意有环图容易导致无限执行、证据混乱、权限重复申请和责任不清。
```

### 5.13 `ExecutorPolicy`

职责：

- 描述某类 Move 应由谁执行。

示例：

```yaml
ExecutorPolicy:
  preferred:
    type: small_model
    capability: extraction
  fallback:
    - type: tool
    - type: medium_model
  audit:
    sample_rate: 0.1
    auditor: large_model
```

设计重点：

- 大模型统领，不等于大模型执行一切。
- 小模型执行，不等于小模型无人审计。

### 5.14 `PermissionRequest`

职责：

- 表示能力包或 Move 请求某种权限。

关键属性：

```yaml
PermissionRequest:
  id: string
  requested_by:
    package_id: string
    move_id: string
  permission:
    type: filesystem.write | shell.run | network.write | federation.share
    scope: object
  preview:
    expected_action: string
    expected_side_effects: SideEffectDeclaration
    rollback_plan: string
  status: pending | approved | denied | expired
```

不可变规则：

- 执行时的请求必须与批准时的 preview 绑定。
- 如果执行内容变了，批准失效。

### 5.15 `EvidenceRecord`

职责：

- 记录每个 Move 发生了什么。

关键属性：

```yaml
EvidenceRecord:
  id: string
  run_id: string
  move_id: string
  package_id: string
  executor: ExecutorRef
  input_ref: Ref
  output_ref: Ref
  status: success | failure | partial | skipped | cancelled
  timestamps:
    started_at: timestamp
    ended_at: timestamp
  side_effects: SideEffectActual[]
  verification:
    schema_valid: boolean
    postconditions_passed: boolean
    audit_status: not_audited | passed | failed
  errors: ErrorRecord[]
```

设计重点：

- Evidence 不是日志。
- Evidence 是系统可复盘、可审计、可恢复的最小事实单元。

### 5.16 `LensDefinition` 与 `LensProjection`

职责：

- `LensDefinition` 定义如何从状态和证据生成视图。
- `LensProjection` 是某一时刻渲染给人类的结果。

关键属性：

```yaml
LensDefinition:
  id: string
  reads:
    - evidence
    - move_status
    - decision_request
    - permission_request
  sections:
    - id: risks
      query: string
    - id: pending_decisions
      query: string

LensProjection:
  lens_id: string
  generated_at: timestamp
  source_refs: Ref[]
  sections: object[]
  actions:
    - approve
    - deny
    - request_more_evidence
```

边界：

- Lens 不能写真相。
- Lens Action 必须转成 `DecisionRequest` 或 `PermissionRequest`。

### 5.17 `PainSignal`

职责：

- 表示系统疼痛。

来源：

- 同一 Move 重复失败。
- 同一能力包质量下降。
- 用户频繁撤销或打断。
- 成本异常升高。
- 证据缺失率升高。
- 权限请求过多。
- Lens 中长期存在阻塞。

关键属性：

```yaml
PainSignal:
  id: string
  source: move | package | lens | permission | human_interaction | federation
  severity: low | medium | high | critical
  evidence_refs: EvidenceRef[]
  hypothesis: string
  suggested_mutation: MutationProposalRef
```

### 5.18 `MutationProposal`

职责：

- 表示能力、协议、权限、Lens、Move Graph 的改进建议。

关键属性：

```yaml
MutationProposal:
  id: string
  source_pain_signal: PainSignalRef
  target:
    type: capability_package | move | lens | permission_policy | assembly
  proposed_change: object
  expected_benefit: string
  risk: string
  dry_run_plan: string
  approval_required: true
```

不可变规则：

- Mutation 只能是提案。
- 不能自动合并到当前真相。

### 5.19 `FederationNode`

职责：

- 表示其他超级个体、团队或能力服务。

关键属性：

```yaml
FederationNode:
  id: string
  public_capabilities: CapabilityAdvertisement[]
  trust_relationship: TrustRelationship
  share_policy: SharePolicy
  accepted_protocols:
    - cyber-body.federation/v0.1
```

联邦只交换：

- 能力声明。
- 请求。
- Evidence 摘要。
- Artifact 引用。
- Decision 请求。
- 不共享私有记忆，除非明确授权。

## 7. 信息流转总览

### 7.1 启动流

```text
App starts
  -> BodyKernel loads body.yaml
  -> SchemaRegistry loads schemas
  -> PackageLoader scans installed packages
  -> SlotRegistry validates package slots
  -> PermissionKernel loads grants/revoked
  -> TrustKernel loads trust scores
  -> EvidenceStore indexes recent runs
  -> LensRenderer builds default dashboard
```

失败处理：

- schema 加载失败：进入 recovery mode。
- 包校验失败：包进入 quarantined。
- 权限文件损坏：全部高风险权限失效。
- evidence 索引失败：可重建索引，不删除原始证据。

### 7.2 能力包安装流

```text
select package
  -> inspect capability.yaml
  -> validate manifest schema
  -> validate move schemas
  -> validate lens schemas
  -> resolve dependencies
  -> run contract tests
  -> install disabled
  -> sandbox dry run
  -> show permission requests
  -> human approves limited grants
  -> enable observe/propose level
```

关键点：

- 安装不等于启用。
- 启用不等于授权执行。
- 授权不等于永久信任。

### 7.3 张力显影流

```text
human expresses vague pain
  -> ProbeSession starts
  -> Probe asks / mirrors / compares / requests examples
  -> TensionField is drafted
  -> Lens shows current understanding and weak points
  -> human corrects
  -> PossibilityMap is generated
  -> PromiseContract draft is proposed
  -> human accepts / edits / rejects
```

输出：

- `TensionField`
- `PossibilityMap`
- `PromiseContract`
- `DecisionRequest`

### 7.4 Promise 到能力装配流

```text
PromiseContract active
  -> CapabilityMatcher searches installed packages
  -> missing capabilities identified
  -> AssemblyPlanner proposes package combination
  -> PermissionKernel checks required permissions
  -> TrustKernel checks automation level
  -> human approves assembly
  -> CapabilityAssembly created
```

设计重点：

- Promise 不直接执行。
- Promise 先进入 Assembly。
- Assembly 再展开 Operation 和 Move。

### 7.5 Move Graph 规划流

```text
CapabilityAssembly
  -> OrchestratorBrain decomposes into Operations
  -> Operations expand to Verifiable Moves
  -> MoveRuntime validates graph
  -> PermissionKernel preflights side effects
  -> ExecutorRouter assigns executors
  -> checkpoint plan created
```

Move Graph 验证：

- 图默认必须无环。
- 并行节点必须没有写冲突。
- side effect 节点必须有权限。
- human interrupt 节点必须有明确问题和默认策略。
- loop 必须有 `LoopController`。

### 7.6 Move 执行流

```text
MoveNode ready
  -> check preconditions
  -> check permission
  -> mount minimal context
  -> select executor
  -> execute
  -> validate output schema
  -> check postconditions
  -> write EvidenceRecord
  -> update run state
  -> notify LensRenderer
```

失败处理：

- 可重试失败：按 retry policy。
- 权限缺失：生成 PermissionRequest。
- 输出 schema 错误：生成 failed Evidence。
- executor 不可用：fallback 或 blocked。
- side effect 部分成功：进入 recovery policy。

### 7.7 人类审批流

```text
PermissionRequest / DecisionRequest
  -> Decision Inbox
  -> Lens shows preview, evidence, risk, alternatives
  -> human approves / denies / edits / asks for more evidence
  -> decision persisted
  -> runtime resumes / replans / cancels
```

关键规则：

- 批准绑定 preview。
- preview 变更则批准失效。
- 高风险动作不能被默认策略自动批准。
- 低风险重复动作可用批量授权，但要有撤销入口。

### 7.8 Lens 渲染流

```text
Evidence / RunState / Permissions / Decisions / PainSignals
  -> LensDefinition query
  -> LensProjection generated
  -> UI renders projection
  -> human action creates request/event
```

Lens 不是状态源。

Lens Projection 可以缓存，但必须能追溯 source refs。

### 7.9 Pain 到 Mutation 流

```text
repeated failures / high cost / user interruption
  -> PainSignal generated
  -> MutationGate diagnoses
  -> MutationProposal drafted
  -> sandbox dry run
  -> Lens shows benefit/risk
  -> human approves
  -> package/policy/schema updated
```

Mutation 不能直接修改系统。

### 7.10 联邦协作流

```text
local Promise needs external capability
  -> FederationBus discovers CapabilityAdvertisement
  -> TrustKernel checks relationship
  -> SharePolicy filters context
  -> remote request sent
  -> remote returns EvidenceSummary / ArtifactRef / DecisionRequest
  -> local EvidenceStore records exchange
  -> Lens shows contribution and risk
```

联邦默认最小共享。

## 8. 核心服务详细设计

### 8.1 `PackageLoader`

职责：

- 扫描能力包。
- 校验 manifest。
- 解析依赖。
- 管理安装状态。
- 执行安装、禁用、卸载、升级。

状态机：

```text
discovered
  -> invalid
  -> installed_disabled
  -> sandboxed
  -> enabled_observe
  -> enabled_propose
  -> enabled_sandbox
  -> enabled_auto_low_risk
  -> quarantined
  -> uninstalled
```

设计规则：

- 新包默认 `installed_disabled`。
- contract test 失败不能启用。
- 权限异常直接 quarantined。
- 升级必须先复制旧 instance 状态，再运行 migration。

### 8.2 `SchemaRegistry`

职责：

- 管理 schema dialect。
- 管理 `$ref` 解析。
- 管理 schema 版本。
- 校验所有协议对象。

引用规则：

- 包内相对引用从包根解析。
- `.body/schemas` 为核心协议 authority。
- 外部 `$ref` 默认禁止，除非 registry 显式信任。
- 缺失引用必须失败，不允许忽略。

### 8.3 `SlotRegistry`

职责：

- 定义身体槽位。
- 限制槽位可用 Move 类型。
- 限制槽位默认权限上限。

示例规则：

```yaml
slot: muscle
allowed_verbs:
  - run
  - write
  - sync
default_permissions:
  filesystem.write: false
  shell.run: false
requires_approval_for:
  - side_effect.any
```

### 8.4 `PermissionKernel`

职责：

- 接收权限请求。
- 生成审批预览。
- 绑定批准和执行内容。
- 拦截 side effect。
- 记录授权和撤销。

执行门：

```text
Move wants side effect
  -> PermissionKernel checks grant
  -> compare grant preview hash with actual request
  -> allow / deny / require human approval
```

关键规则：

- 权限按 package、move、scope、time、preview 绑定。
- 写文件、联网、shell、联邦共享默认禁止。
- UI 不能绕过 PermissionKernel。

### 8.5 `TrustKernel`

职责：

- 管理能力包信任等级。
- 根据信任等级限制自动化。
- 从 Evidence、Audit、PainSignal 更新信任。

信任等级：

```text
0 observed_only       只观察，不行动
1 propose             只提案
2 draft               产出草稿
3 sandbox             沙盒执行
4 low_risk_auto       低风险自动
5 bounded_agent       明确边界内代理执行
```

降级条件：

- schema 违规。
- 未授权 side effect。
- 审计失败。
- 用户撤销。
- PainSignal 持续高发。

### 8.6 `ContextMountService`

职责：

- 将文件、资源、记忆、工具、外部数据以最小必要方式挂载给 Move。

挂载类型：

- `RootMount`：文件根目录。
- `ResourceMount`：外部资源。
- `MemoryMount`：经过策略过滤的记忆。
- `ToolMount`：工具能力。
- `FederationMount`：外部协作者能力摘要。

规则：

- Move 只能看到 input_ref 和 mount policy 允许的上下文。
- 大模型不能默认获得全部项目。
- 小模型应获得更小的上下文切片。

### 8.7 `MoveRuntime`

职责：

- 验证 MoveGraph。
- 执行 Move。
- 管理 checkpoint、retry、interrupt、resume。
- 管理并行和冲突。

状态机：

```text
pending
  -> ready
  -> running
  -> waiting_permission
  -> waiting_human
  -> success
  -> failure
  -> partial
  -> skipped
  -> cancelled
```

并行规则：

- 只读 Move 默认可并行。
- 写入 Move 必须声明 target。
- 同一 target 写入不能并行。
- 联邦 Move 必须考虑远端超时和部分结果。

### 8.8 `ExecutorRouter`

职责：

- 根据 Move 类型、成本、风险、信任、上下文大小选择执行器。

选择规则：

| Move 类型 | 首选 | 审计 |
|---|---|---|
| scan | 工具 | 规则校验 |
| extract | 小模型 | 抽样中/大模型 |
| classify | 小模型 | 抽样 |
| validate | 规则程序 | 大模型解释失败 |
| draft | 中模型 | 大模型评审 |
| rank | 中/大模型 | 人类确认高风险 |
| run | 工具/脚本 | Evidence 强制 |
| write | 工具 | 人类授权 + diff |
| ask_human | 人类 | DecisionRecord |
| audit | 大模型/规则 | Evidence |

### 8.9 `EvidenceStore`

职责：

- 保存 EvidenceRecord。
- 维护 run 索引。
- 支持 replay。
- 支持 Lens 查询。

设计规则：

- 原始 evidence append-only。
- 派生索引可重建。
- Evidence 不能被能力包直接删除。
- 删除只能生成 tombstone 或 privacy redaction record。

### 8.10 `LensRenderer`

职责：

- 根据 LensDefinition 生成 LensProjection。
- 把状态解释给人类。
- 把 UI action 转成 request/event。

Lens 类型：

- `TensionLens`
- `PromiseLens`
- `AssemblyLens`
- `MoveLens`
- `EvidenceLens`
- `RiskLens`
- `DecisionLens`
- `PainLens`
- `MutationLens`
- `FederationLens`

### 8.11 `MemoryGarden`

职责：

- 管理候选记忆。
- 压缩、合并、遗忘、冲突检测。
- 为 Move 提供可引用记忆。

记忆来源：

- 用户确认。
- Evidence 总结。
- PainSignal。
- MutationProposal。
- 运行复盘。

记忆原则：

- 记忆不是聊天记录。
- 记忆必须有来源和置信度。
- 私有记忆默认不联邦共享。

### 8.12 `MutationGate`

职责：

- 从 PainSignal 生成改进提案。
- 沙盒验证提案。
- 等待人类批准。

Mutation 类型：

- 新 Move。
- 修改 Move schema。
- 新 Lens。
- 权限策略调整。
- 包升级。
- 信任降级。
- 新能力包建议。

### 8.13 `FederationBus`

职责：

- 管理超级个体之间的能力发现和协作。

协议对象：

- `CapabilityAdvertisement`
- `FederationRequest`
- `FederationResponse`
- `EvidenceSummary`
- `SharePolicy`
- `TrustRelationship`

规则：

- 默认不共享 raw file。
- 默认不共享私有记忆。
- 分享必须经过 SharePolicy。
- 远端结果必须本地 Evidence 化。

## 9. 运行语义设计

### 9.1 Graph 语义

MoveGraph 默认是 DAG。

允许：

- 顺序依赖。
- 并行分支。
- 条件分支。
- 人类中断。
- 子图。
- 有界循环控制器。

不允许：

- 任意回边。
- 无退出条件循环。
- 无 checkpoint 的循环。
- 无 Evidence 的后台动作。

### 9.2 LoopController

循环必须写成控制器：

```yaml
loop:
  id: retry-until-schema-valid
  body:
    - draft-output
    - validate-output
  exit_when:
    - validate-output.status == success
  max_iterations: 3
  checkpoint_each_iteration: true
  on_exhausted: ask_human
```

这样有环行为仍然可恢复、可审计。

### 9.3 Checkpoint

checkpoint 保存：

- run state。
- completed moves。
- pending moves。
- permission waits。
- human waits。
- evidence refs。
- mounted context refs。
- executor assignments。

恢复时不能重新执行已成功且有 side effect 的 Move，除非 rollback 后明确重试。

### 9.4 Interrupt

interrupt 类型：

- `human_decision_required`
- `permission_required`
- `missing_context`
- `quality_gate_failed`
- `cost_limit_reached`
- `risk_detected`
- `federation_response_wait`

interrupt 必须有：

- 原因。
- 当前证据。
- 推荐选项。
- 默认策略。
- 超时策略。

## 12. MVP 架构切片

不要一开始做完整产品。

应按架构闭环切片。

### 12.1 Slice 0：协议读取与校验

目标：

```text
读取 capability.yaml
  -> 校验 manifest
  -> 校验 move
  -> 显示包能力和权限请求
```

验证：

- 无 UI 也能命令行校验。
- schema 错误能定位。
- 缺失引用 fail closed。

### 12.2 Slice 1：无副作用 Move Runtime

目标：

```text
运行 observe / scan / extract / classify / validate
  -> 写 Evidence
  -> 生成 LensProjection
```

限制：

- 不写文件。
- 不联网。
- 不执行任意 shell。

### 12.3 Slice 2：Lens Workspace

目标：

```text
从 Evidence 渲染 MoveLens / EvidenceLens / DecisionLens
```

验证：

- UI 展示都能追溯 source refs。
- UI action 只能生成 request。

### 12.4 Slice 3：Permission Gate

目标：

```text
让 write / shell / network Move 必须走 preview -> approval -> execution
```

验证：

- preview 变更导致 approval 失效。
- 被拒绝动作不能执行。
- 所有批准写入 Evidence。

### 12.5 Slice 4：Package Lifecycle

目标：

```text
install disabled -> sandbox -> enable observe/propose -> trust upgrade
```

验证：

- contract test 失败不能启用。
- 包可禁用和卸载。
- evidence 不被删除。

### 12.6 Slice 5：Promise 到 Assembly

目标：

```text
TensionField -> Promise -> CapabilityAssembly -> MoveGraph
```

验证：

- Promise 不直接执行。
- Assembly 能解释为什么选这些包。
- MoveGraph 可校验。

## 13. 关键架构风险

| 风险 | 后果 | 架构约束 |
|---|---|---|
| 能力包太像 prompt 包 | 不可验证、不可治理。 | manifest、schema、Move、Evidence、tests 必须齐全。 |
| Move 粒度太粗 | 小模型无法可靠执行。 | 强制 Move 原子化判定。 |
| Step 粒度暴露 | 系统变成脚本解释器。 | Step 只在 Move 内部，不做调度单位。 |
| UI 拥有状态 | 文档和运行真相漂移。 | UI 只读 LensProjection。 |
| 权限只是 metadata | 越权执行。 | PermissionKernel 是执行门。 |
| Evidence 只是日志 | 无法复盘和审计。 | Evidence 是结构化事实对象。 |
| 任意有环图 | 无限执行、恢复困难。 | DAG + LoopController。 |
| 大模型包办一切 | 成本高、不可验证。 | ExecutorRouter 按 Move 类型分工。 |
| 用户审批过多 | 决策地狱。 | HumanBandwidth + batch decision + trust gradient。 |
| 联邦共享过度 | 隐私和责任风险。 | SharePolicy 默认最小共享。 |

## 14. 设计完成度判断

一份能力包设计只有满足以下条件，才算架构可落地：

1. 有 `capability.yaml`。
2. 有 schema。
3. 有 Move 列表。
4. 每个 Move 有输入输出、权限、副作用、证据要求。
5. 有至少一个 Lens。
6. 有 contract tests。
7. 有安装、启用、禁用、卸载语义。
8. 有版本和迁移规则。
9. 有失败行为。
10. 能在一个 Promise Assembly 中说明自己的位置。

一个系统切片只有满足以下条件，才算闭环：

```text
Package
  -> Install
  -> Permission
  -> MoveGraph
  -> Execute
  -> Evidence
  -> Lens
  -> HumanDecision
  -> Resume or Finish
```
