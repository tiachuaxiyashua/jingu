# 临时讨论：相业架构层级细节与运行机制

> 状态：临时讨论稿，不是当前真相源。
>
> 合并条件：只有当本稿中的层级边界、文件契约、风险治理、藏管理和并发机制经过讨论确认后，才可吸收到 `00-当前真相源-人工智能软件社会相业架构.md`。

## 0. 本稿目标

本稿解决一个问题：如何从最简单的相业关系，逐步演进成可运行、可治理、可复盘、可迁移的软件社会。

根律仍然保持简单：

1. 相承载稳定存在。
2. 业改变相。
3. 业由因起，向愿而行。
4. 律定边界，法成能力，位明责任，行者承业而行。
5. 果必须携证，证入藏，藏再成为新因缘。
6. 人是愿主、授权源和最高裁决源。

任何新增层级、机制、文件、调度策略，都只是这些根律的展开，不能变成新的根概念。

## 1. 前沿趋势边界

这里的前沿趋势不是照搬外部框架，而是抽取对本架构有边界作用的工程事实。

本稿在 2026-05-12 参考的前沿基线：

- JSON Schema Core：schema 应声明方言、标识符、引用和结果结构。
- Semantic Versioning：公开契约需要明确破坏性变更、兼容新增和补丁修复。
- Model Context Protocol：工具和资源访问需要根目录边界、授权和宿主管辖。
- OpenAI 工具调用实践：工具参数应结构化、可严格校验，高风险调用应受安全门控。
- LangGraph 持久化与可恢复执行：长运行状态需要检查点、恢复、人类介入和重放能力。

| 趋势 | 对相业架构的要求 |
|---|---|
| 结构化契约成为默认 | 相、业、律、证、藏必须有 schema，不能只靠自然语言解释 |
| 可恢复执行成为底座 | 任何长业都必须能暂停、恢复、重放、拒收，不能只靠会话上下文 |
| 高风险工具调用需要人类确认 | 外部副作用、写文件、删除、花钱、发消息等必须先形成可审查的待授权业 |
| 根目录和能力边界由宿主管辖 | 行者不能靠自觉守边界，文件根、工具能力和外部资源必须由运行底座拦截 |
| 追踪和评估成为生产能力 | 不能只看最终果，必须能评估每次行、工具调用、拒收、升级和仲裁 |
| 版本兼容必须显式化 | 法、律、位、业模板、schema 都要有版本和迁移策略 |
| 非可信因相必须隔离 | 外部网页、用户粘贴、第三方文档不能直接进入高权限上下文，只能先结构化抽取 |
| 超大项目会超出上下文窗口 | 必须用索引、切片、装境业、遗漏证和递归等级化视野治理，不能让单个行者假装读完全局 |
| 大模型更强但仍会犯错 | 架构不能假设模型一次正确，必须用证、拒收、复验、风险升级和小范围迭代兜底 |

因此，相业架构不能退化成“一个更聪明的行者”。它必须成为一个能够装载更强模型、更多工具、更复杂协作，同时仍保持可控的外骨骼。

## 2. 从最小相业开始演进

### 2.1 零阶：只有相

最小系统只有文件：`.软件社会/相/因/`、`.软件社会/相/愿/`、`.软件社会/相/果/`。

这时系统只能保存东西，不能可靠改变东西。

能做：

- 保存用户表达。
- 保存目标草案。
- 保存结果草稿。

不能做：

- 证明结果从何而来。
- 判断谁有权修改。
- 追踪修改是否污染其他相。
- 让下游拒收。

### 2.2 一阶：加入业

加入 `业/` 后，系统有了最小变化单位。最小业只需要 `ye_id`、`schema`、`因`、`愿`、`律`、`行.status`、`果.expected`、`证.required`。

此时系统能回答：

- 为什么改。
- 要改成什么。
- 什么算完成。
- 哪些检查必须通过。

### 2.3 二阶：加入只追加证相

单业仍会出现“自称完成”。因此加入 `相/证/事件流/`，把扫描、验收、拒收、授权、审计都保存为只追加证相。只追加证相不覆盖旧事实，每条至少包含 `event_id`、`ye_id`、`kind`、`result`、`created_at`。

此时系统开始具备复盘能力。

### 2.4 三阶：加入律、位、法、行者

当业变复杂，需要拆开四件事：

| 概念 | 解决的问题 |
|---|---|
| 律 | 什么不能做、什么必须升级、什么算失败 |
| 位 | 从哪个责任视角判断 |
| 法 | 用什么可复用方法成事 |
| 行者 | 谁或什么承接本次行 |

一个业可以让多个行者处于多个位共同承接，例如同时引用 `文档架构位`、`反方评审位`、`术语一致性扫描法`、`影响面扫描法`、`small-model-scan` 和 `frontier-model-review`。

关键点：不是行者组织世界，而是业根据因、愿、律、位、法召行者。

### 2.5 四阶：加入业网

多个业开始互相引用，例如：`显影业 -> 设计业 -> 写作业 -> 评审业 -> 清理业 -> 下游拒收业`。

但业网不是固定路线。它是事实发生后的关系投影：

- 一个业可以派生多个业。
- 一个业可以拒收另一个业的果。
- 一个业可以修正另一个业的果。
- 一个仲裁业可以裁决多个业的冲突。
- 一个风险升级业可以把判断交给更高位。

主动运行时可以采用有向关系，但不能让路线图压过业本身。

### 2.6 五阶：加入藏、信、险、镜

复杂系统必须沉淀：

| 概念 | 加入原因 |
|---|---|
| 藏 | 防止重复尝试，保存经验、偏好、环境事实、失败复盘 |
| 信 | 记录某个行者、法、位在特定条件下是否可靠 |
| 险 | 累积多个小风险，防止局部安全合成全局危险 |
| 镜 | 把复杂运行状态投影给人类，让人知道何时介入 |

至此，相业架构从单文件变化演进成软件社会。

## 3. 层级设计

这里的层不是新的根概念，而是实现时的责任边界。每一层都只处理相和业。

### 3.1 文件相层

职责：

- 保存所有可迁移存在。
- 保证每个相有稳定路径、版本、摘要和状态。
- 保证同一个事实不会散落成多个互相冲突的真相源。

主要目录包括：`相/因/`、`相/愿/`、`相/律/`、`相/位/`、`相/法/`、`相/行者/`、`相/果/`、`相/证/`、`相/藏/`、`相/镜/`、`相/信/`、`相/险/`。

必须提供：

- `xiang_id`
- `schema`
- `version`
- `status`
- `created_at`
- `updated_at`
- `source_refs`
- `supersedes`
- `superseded_by`
- `checksum`

不能做：

- 直接执行变化。
- 自行判断完成。
- 覆盖只追加证相。

### 3.2 契约层

职责：

- 定义 schema。
- 定义状态机。
- 定义引用解析。
- 定义版本迁移。
- 定义缺字段恢复策略。

契约文件包括：`契约/schema/xiang.schema.json`、`契约/schema/ye.schema.json`、`契约/schema/lv.schema.json`、`契约/schema/zheng.schema.json`、`契约/state/ye-state.yaml`、`契约/state/xiang-state.yaml`、`契约/migration/xiangye.v0-to-v1.yaml`。

契约层必须回答：

- 这个文件是什么类型。
- 它使用哪个 schema 版本。
- 它引用的相如何解析。
- 缺字段时是拒收、补默认值，还是派生修复业。
- 版本不兼容时是否允许自动迁移。

不能做：

- 不经业直接修改业务内容。
- 用自然语言替代机器可检查字段。

### 3.3 业核层

职责：

- 创建业。
- 推进业状态。
- 挂载因、愿、缘、律、位、法、行者。
- 生成果和证。
- 派生后续业。
- 管理拒收、仲裁、升级。

业状态机主线是 `拟立 -> 待承接 -> 运行中 -> 待验收 -> 完成`；运行中可进入 `暂停/恢复/仲裁/升级/废弃`，待验收可进入 `拒收 -> 修正业`。

业核层最重要的边界：

- 业不是行者会话。
- 业不是固定路线节点。
- 业记录必须在行者替换后仍可继续。
- 高风险业必须先形成待授权果，再执行外部副作用。

### 3.4 行者适配层

职责：

- 把模型、会话、工具、脚本、人类专家、外部服务统一适配为行者。
- 管理行者能力、上下文、权限、成本、可靠性和隔离。
- 根据业的律和位选择行者。

行者相最小字段包括：`xiang_id`、`schema`、`type`、`capabilities`、`context_policy`、`tool_policy.filesystem_roots`、`tool_policy.write_requires_approval`、`trust.default_level`。

不能做：

- 自己成为真相源。
- 私自扩大文件根。
- 私自调用高风险工具。
- 把未验证因相放进高权限上下文。

### 3.5 治理层

职责：

- 执行根律。
- 执行权限律、风险律、质量律、成本律、安全律。
- 管理授权、拒绝、升级、冻结和审计。

治理层不是一个特殊大脑。它本身也由相和业组成：

- 律相：定义边界。
- 授权业：请求人类或高位行者授权。
- 风险评估业：计算险。
- 仲裁业：处理冲突。
- 审计证：记录谁在何时批准了什么。

治理层必须在运行底座强制执行，不能只显示在界面上。

### 3.6 沉淀层

职责：

- 管理藏、信、险、证。
- 控制哪些经验可被检索。
- 控制哪些经验已经过时。
- 防止藏污染和负迁移。

沉淀层的核心不是“记住更多”，而是：

- 只把通过证支撑的内容沉淀为藏候选。
- 只有适用范围明确的藏才能被自动检索。
- 过期、冲突、低信内容必须降权。
- 每次引用藏都要记录使用痕迹。

### 3.7 镜层

职责：

- 给人类展示系统状态。
- 呈现当前业、风险、分歧、待授权项、证链和下游影响。
- 支持人类插手、暂停、授权、拒绝、裁决。

镜层不能做：

- 成为真相源。
- 隐藏风险。
- 用绿色状态替代证。
- 把人类变成频繁点击的审批机器。

镜层应该让人类看到：

- 系统为什么这样做。
- 哪些判断已经有证。
- 哪些判断仍是推测。
- 当前风险为什么升级。
- 如果不介入会发生什么。

### 3.8 联邦与迁移层

职责：

- 打包和迁移法、位、律、业模板、证样本、评估集。
- 管理版本、兼容性、签名、来源和信任等级。
- 支持多个超级个体协作。

可迁移单元不应叫“大能力集合”。应该拆成：

| 可迁移相 | 内容 |
|---|---|
| 法包 | 一组方法、模板、操作步骤、适用边界 |
| 位包 | 一组职责位置、验收权、上报条件 |
| 律包 | 一组机器可执行律和人类可读根律说明 |
| 业模板 | 常见业的最小结构和验收证 |
| 评估包 | 反例、样本、验收题、红队题 |
| 藏种子 | 可选的经验沉淀，必须带来源和适用范围 |

## 4. 关键运行机制

### 4.1 藏管理机制

藏的生命周期是：`候选 -> 待证 -> 可检索 -> 被引用 -> 衰减 -> 过期 -> 清理 / 重验`。

藏相最小字段包括：`xiang_id`、`schema`、`claim`、`source_refs`、`scope.applies_to`、`confidence`、`expires_when`、`supersedes`、`negative_examples`。

藏管理必须有四个拦截点：

1. 入藏前：没有证，不能入藏。
2. 检索时：范围不匹配，不能装载。
3. 使用时：必须记录哪个业引用了它。
4. 修改后：影响面扫描业必须判断旧藏是否过期。

防止负迁移：

- 藏不能全局默认生效。
- 藏必须有适用范围。
- 藏必须有反例。
- 藏必须有过期条件。
- 相互冲突的藏必须触发仲裁业。

### 4.2 律与权限机制

律分三层：

| 层级 | 内容 | 谁能改 |
|---|---|---|
| 根律 | 人类价值、不可越界事项、最高授权边界 | 人类 |
| 运行律 | 文件根、工具权限、成本阈值、风险阈值 | 人类授权的治理业 |
| 业律 | 本次业的质量线、拒收条件、交付边界 | 立业者或授权行者 |

权限执行必须采用“先预览，后授权，再执行”：

```text
拟行 -> 生成预览果 -> 风险评估 -> 授权 / 拒绝 / 编辑 -> 执行 -> 留证
```

高风险操作不能直接执行：

- 删除文件。
- 批量改写。
- 对外发送。
- 付款。
- 发布。
- 调用外部高敏服务。
- 读取敏感根目录。

授权证必须绑定：

- 授权人。
- 授权时间。
- 授权对象。
- 预览摘要。
- 参数摘要。
- 有效期。
- 是否一次性。
- 执行后的证。

### 4.3 文档防污染机制

文档污染的典型形式：

- 新旧术语混用。
- 当前真相源和历史文档并列生效。
- 修改主文档但入口未改。
- 修改概念但案例未改。
- 旧藏继续被检索。
- 示例仍引用废弃路径。

每次重要文档修改必须派生四个业：

| 业 | 目的 |
|---|---|
| 影响面扫描业 | 找出受影响文件、目录、引用、案例、入口 |
| 术语一致性业 | 扫描旧词、同义词、反例、混用表述 |
| 下游消费检查业 | 检查入口、索引、临时稿、历史稿是否会误导 |
| 藏清理业 | 标记旧藏过期、被取代或需要重验 |

写文档不能只改可见段落。必须同时处理：

- 当前文件。
- 入口文件。
- 引用路径。
- 示例。
- 对比表。
- 历史归档说明。
- 藏相。
- 质量证。

### 4.4 风险累积与逐级上报

风险不是单次业字段，而是险相累积。

险相最小字段包括：`xiang_id`、`schema`、`risk_type`、`local_level`、`cumulative_level`、`sources`、`impact`、`threshold_hit`、`required_escalation`。

风险累积律：

| 条件 | 结果 |
|---|---|
| 单业低风险，但连续修改同一真相源 | 累积为中风险 |
| 多个低风险业共同影响入口、 schema 或根律 | 累积为高风险 |
| 涉及删除、发布、付款、外部承诺 | 直接高风险 |
| 影响多人协作或长期决策 | 至少中风险 |
| 行者低信且任务高影响 | 升级 |

逐级上报链是：`原子行者 -> 专业位行者 -> 统筹位行者 -> 仲裁位行者 -> 人类愿主`。

解释：

- 原子行者适合小范围、低风险、可验证动作。
- 专业位行者负责专业判断。
- 统筹位行者负责跨文件、跨业、跨目标影响。
- 仲裁位行者负责冲突裁决，但必须受根律和人类授权管辖。
- 人类愿主是最高裁决源。实现时可以把人类投影为最高位行者，但概念上人不是普通行者资源。

上报必须携带：

- 发生了什么。
- 为什么当前层级不能决策。
- 有哪些候选方案。
- 每个方案的风险。
- 不决策的后果。
- 推荐方案和反方意见。

### 4.5 文件并发机制

文件驱动系统必须正视并发。否则多个业会同时改同一相，造成真相分叉。

最低机制：

| 机制 | 作用 |
|---|---|
| 相版本号 | 判断写入时是否基于最新版本 |
| 校验摘要 | 防止无感覆盖 |
| 写前锁 | 防止两个业同时写同一相 |
| 写后证 | 记录本次变化 |
| 只追加证相 | 防止历史被覆盖 |
| 合并业 | 处理并发修改冲突 |
| 仲裁业 | 处理无法自动合并的冲突 |

写入协议是：`读取相版本 -> 生成修改预览 -> 获取写锁 -> 校验版本未变 -> 写入新版本 -> 追加证相事件 -> 释放锁`。如果版本已变，则 `停止写入 -> 生成冲突证 -> 派生合并业 -> 必要时升级给更高位`。

禁止：

- 行者直接覆盖文件。
- 无证合并。
- 把运行日志当最终相。
- 把失败写入吞掉。

### 4.6 质量与一次做对机制

一次做对不是一次生成完美，而是让错误在最小范围内被发现。

质量律至少分四级：

| 等级 | 要求 |
|---|---|
| 格式线 | schema、表格、链接、路径、字段通过 |
| 语义线 | 概念一致、无明显冲突、能被下游消费 |
| 证线 | 关键判断有证，假设和未验证点显式标出 |
| 反方线 | 高价值果经过反方攻击或下游拒收测试 |

携证之果必须说明：

- 引用了哪些因。
- 依赖哪些缘。
- 受哪些律管辖。
- 谁以什么位、用什么法完成。
- 哪些判断有证。
- 哪些地方只是推测。
- 下游如何使用。
- 下游如何拒收。

### 4.7 非可信因相隔离机制

非可信因相包括：

- 网页内容。
- 第三方文档。
- 用户粘贴的大段文本。
- 外部工具返回。
- 历史过时文档。
- 低信行者生成的果。

处理律：

1. 非可信因相只能进入低权限解析业。
2. 解析业只产出结构化字段，不产出高权限指令。
3. 高权限业只能读取结构化后的候选因相。
4. 外部文本不得直接进入根律、运行律或高权限行者上下文。
5. 如果外部文本影响工具调用，必须先经过风险评估和授权。

### 4.8 可恢复执行机制

长业不能靠一段会话活着。检查点至少包括：业状态检查点、行者上下文摘要、已完成行记录、副作用执行证、待授权项、失败原因、恢复入口。

恢复律：

- 已有证的副作用不能重复执行。
- 未完成行可以重试。
- 不确定是否完成的行必须派生核查业。
- 高风险恢复必须先进入待授权状态。
- 恢复后必须追加恢复证。

### 4.9 评估与回归机制

每个重要法、律、位、业模板都应有评估集。

评估集包括：

- 正例。
- 反例。
- 边界样本。
- 历史失败样本。
- 对抗样本。
- 人类裁决样本。

评估不只评果，也评运行轨迹：

- 是否越权。
- 是否遗漏因。
- 是否引用过时藏。
- 是否没有上报风险。
- 是否没有保留证。
- 是否把低信结论当事实。

### 4.10 非用户日志系统

日志系统是必要的非用户功能，但不是新的根概念。它的职责是支持排障、性能分析、安全审计、恢复和运行观测；只有被业引用、被验收或被风险评估命中的日志片段，才会提升为证相、险相或信相。

日志分层：

| 日志类 | 主要用途 | 是否默认进入真相 |
|---|---|---|
| 调试日志 | 开发排障、定位异常分支 | 否，只短期保留 |
| 运行日志 | 记录业状态推进、行者调用、工具调用、重试 | 否，命中问题后可提升为证相 |
| 审计日志 | 记录授权、拒绝、越权拦截、高风险预览和执行 | 是，以审计证形式保存 |
| 安全日志 | 记录敏感根访问、外部调用、脱敏、阻断 | 是，必要时生成险相 |
| 性能日志 | 记录耗时、成本、上下文大小、重试次数 | 否，聚合后可生成信相或险相 |
| 质量日志 | 记录质量门、拒收、反方评审、回归结果 | 是，以质量证形式保存 |

日志事件最小字段：

| 字段 | 含义 |
|---|---|
| `event_id` | 日志事件唯一标识 |
| `time` | 发生时间 |
| `level` | `debug/info/warn/error/security/audit` |
| `kind` | 事件类型，如 `tool_call`、`approval`、`quality_gate` |
| `ye_id` | 关联业，没有则为空 |
| `xiang_refs` | 关联相 |
| `actor_ref` | 关联行者或人类授权者 |
| `action_ref` | 关联行 |
| `summary` | 人类可读摘要 |
| `payload_ref` | 大载荷位置，不直接塞进日志主记录 |
| `sensitive` | 是否包含敏感信息 |
| `retention` | 保留策略 |
| `promote_to` | 是否提升为证相、险相或信相 |

日志系统必须遵守：

1. 日志默认不是相业真相源，只是运行底座的观测材料。
2. 审计、安全、质量类日志一旦影响裁决，必须提升为证相。
3. 敏感日志必须脱敏、分级、限权，不能直接暴露给普通行者。
4. 大模型上下文不能无差别塞入完整日志，只能通过检索、摘要和证相引用进入业。
5. 日志必须有轮转、压缩、过期和导出策略，防止无限增长。
6. 日志写入失败不能静默吞掉；若影响审计或恢复，必须阻断高风险业。
7. 日志不能替代证。证必须说明它证明什么，日志只说明发生过什么。

日志到相业的提升路径：

| 触发条件 | 派生业 | 生成相 |
|---|---|---|
| 工具调用失败 | 失败归因业 | 失败证 |
| 授权被拒绝 | 授权复盘业 | 审计证 |
| 多次重试超阈值 | 风险评估业 | 险相 |
| 某行者连续低质量 | 信评估业 | 信相 |
| 敏感根访问被拦截 | 安全审计业 | 安全证、险相 |
| 性能持续恶化 | 性能诊断业 | 性能证、优化候选业 |

日志系统和镜层的关系：

- 日志面向开发者、运维者和治理业。
- 镜面向人类愿主和协作者。
- 镜可以展示日志摘要、异常趋势和待决策点，但不能把原始日志直接当成人类可读真相。
- 高风险场景下，镜必须显示“哪些日志已提升为证，哪些只是辅助材料”。

### 4.11 递归等级化视野治理机制

当项目足够大时，“必要上下文”会超过任何单一行者的上下文空间。这个问题不能靠更长窗口硬扛，也不能靠粗暴摘要遮盖。相业架构必须承认：全局理解不是某个行者一次读完，也不是固定几层组织表能够兜住，而是由业的递归聚合动态生长出来。

核心判断：

1. 不预设固定层数。系统只定义递归聚合协议。
2. 每个聚合业只消费若干下级业的果、证、遗漏证、风险和必要原文。
3. 如果聚合业仍然超出上下文预算，就继续插入中间聚合业。
4. 等级由预算律、风险律、遗漏证和决策需要动态生成。
5. 越上层越看全局结构、风险、冲突和取舍，细节分辨率越低。
6. 越下层越看局部原文、操作细节和事实证，全局分辨率越低。
7. 人类需要看到“当前递归树覆盖了哪里、遗漏了哪里、哪些遗漏会影响裁决”。

这不是人设化，而是等级化。职责位是横向责任视角，等级是纵向视野分辨率。一个架构位可以出现在低层局部业，也可以出现在高层聚合业；差别不是身份，而是上下文分辨率和裁决范围。

递归聚合单元：

| 单元 | 读取 | 生成 | 继续递归条件 |
|---|---|---|---|
| 叶子业 | 原文、文件片段、日志、局部相 | 原子果、原子证、局部遗漏证 | 局部范围仍过大 |
| 聚合业 | 下级果、证、遗漏证、风险、必要原文 | 更高层果、冲突证、覆盖率证 | 聚合后仍超预算或冲突未收敛 |
| 仲裁业 | 冲突包、双方证、风险相、根律 | 裁决果、裁决证 | 裁决风险超授权 |
| 人类裁决业 | 镜层摘要、候选方案、风险、遗漏证 | 授权、取舍、方向裁决 | 人类要求继续下钻 |

新增的不是根概念，而是几类普通业：

| 业类 | 目的 | 果 | 证 |
|---|---|---|---|
| 项目地图业 | 建立目录、模块、依赖、热点、owner、风险入口 | 项目地图相 | 扫描命令、文件摘要、依赖引用 |
| 切片识别业 | 将大项目拆成可由单个行者承接的局部范围 | 切片相 | 边界说明、包含清单、排除清单 |
| 装境业 | 为某个业装配最小必要上下文 | 上下文包果相 | 采用理由、遗漏证、预算使用 |
| 局部侦察业 | 让小行者或工具处理具体切片 | 局部发现果 | 路径、引用、局部证 |
| 聚合评审业 | 汇总多个下级果，找冲突和缺口 | 上层候选果 | 下级证、冲突证、遗漏证 |
| 漏洞追问业 | 对遗漏高风险区域发起补充侦察 | 补充业清单 | 为什么必须补查 |
| 中间聚合业 | 在两个层级之间动态插入 | 中间层果 | 为什么需要新增层级 |

上下文包果相最小字段：

| 字段 | 含义 |
|---|---|
| `context_id` | 本次装境结果标识 |
| `ye_id` | 服务于哪个业 |
| `budget` | 可用上下文预算 |
| `selected_refs` | 被采用的相、文件片段、证、藏 |
| `selected_reason` | 每个采用项为什么进入上下文 |
| `omitted_refs` | 被排除但相关的候选项 |
| `omission_risk` | 遗漏可能造成的风险 |
| `freshness` | 索引和切片是否新鲜 |
| `source_hash` | 关键来源摘要 |
| `rebuild_method` | 如何重建同一上下文包 |

上下文预算律：

| 触发条件 | 处理 |
|---|---|
| 候选上下文超过预算 | 禁止直接截断，必须派生装境业 |
| 关键文件无法装入 | 派生切片识别业或局部侦察业 |
| 遗漏风险高 | 升级给统筹位行者或人类 |
| 索引过期 | 先派生索引刷新业 |
| 多个切片果冲突 | 派生冲突仲裁业 |
| 上下文包无法解释采用理由 | 拒收本次业 |

等级化视野律：

| 视野等级 | 可见内容 | 不应直接吞入 | 必须携带 |
|---|---|---|---|
| 低层视野 | 原文、单文件、小切片、局部日志、局部证 | 全项目战略判断 | 原子证、局部遗漏证 |
| 中层视野 | 若干下级果、局部地图、局部风险、冲突点 | 大量原文全集 | 覆盖率证、冲突证、补查建议 |
| 高层视野 | 项目地图、多个中层果、系统性风险、资源取舍 | 单点实现细节 | 决策依据、遗漏风险、下钻入口 |
| 最高视野 | 价值、授权、不可逆风险、候选方向 | 执行噪音 | 人类可裁决镜、关键证链 |

层数不是这张表固定的。任何一层只要仍然超预算，就可以继续生长出下一层中间聚合业；任何一层只要风险或遗漏过高，也可以向下派生补查业。

递归停止条件：

- 当前业的上下文包在预算内。
- 当前果足以支撑上级判断。
- 遗漏风险低于律定义阈值。
- 下级冲突已经被仲裁或明确保留。
- 继续拆分的收益低于成本。
- 人类愿主或授权高位要求停止。

递归失控防线：

- 深度预算：限制连续聚合或连续下钻深度。
- 成本预算：限制派生业数量、模型成本、工具成本。
- 循环检测：防止反复补查同一范围。
- 收敛证：证明继续拆分收益下降。
- 抽样下钻：上层随机检查下级原始证，防止摘要失真。
- 越级告警：低层发现高风险时可直接生成上报业，不必等待逐层汇总。

防止“摘要幻觉”：

- 摘要必须是果相，不能替代原始相。
- 摘要必须携带来源引用、生成业、生成行者和限制。
- 摘要被下游采用时，必须保留“未覆盖范围”。
- 摘要之间冲突时，不能用更高层摘要掩盖，必须回到切片证或派生补查业。
- 如果全局结论依赖多个摘要，必须列出每个摘要的信和过期条件。

大项目递归运行顺序：

1. 建立或刷新项目地图相。
2. 根据愿和律选择候选切片。
3. 装境业生成上下文包果相。
4. 如果超预算，派生切片识别业、局部侦察业或中间聚合业。
5. 下级业分别产出果、证、遗漏证和风险。
6. 上级聚合业只消费下级果、证、遗漏证、风险和必要原文。
7. 如果上级聚合仍超预算，继续插入中间聚合业。
8. 高风险、关键遗漏或价值取舍升级给更高层聚合业或人类愿主。
9. 形成果后，保留上下文包果相、覆盖率证、遗漏证和递归结构，供复盘和重建。

这意味着：上下文不是一个隐藏 prompt，而是一个可审计、可重建、可拒收的果相。

## 6. 必须补充但尚未定稿的问题

### 6.1 调度权到底在哪里

候选答案：

1. 调度权属于业核层。
2. 调度权属于特殊位行者。
3. 调度权本身也是一种业。

建议：调度不是根概念。调度应表现为一组治理业、派生业和授权业。实现时可以有调度服务，但概念上不能把调度服务变成新的上帝。

### 6.2 业网是否允许环

建议：

- 引用关系允许形成环，因为现实复盘和修正可能互相引用。
- 主动执行链必须有边界：预算、深度、时间、收敛条件、风险阈值。
- 若同一业反复派生修正业，必须触发停机评审业。

也就是说，存储层可以有环，运行层必须有可停止机制。

### 6.3 高位行者如何避免权力过大

高位行者越有全局观，越可能形成新的集中失败点。

防守方式：

- 高位行者只能裁决给定问题，不能无限扩大范围。
- 高位裁决必须携证。
- 高位裁决必须可被人类复查。
- 高位行者的信用也会下降。
- 人类可以冻结高位行者。

### 6.4 藏和证如何避免膨胀

必须有清理业：

- 删除无引用临时相。
- 降权低信藏。
- 合并重复藏。
- 标记过期证。
- 对长期未使用法进行冷藏。

清理不能实际抹除审计证事件，只能改变可检索状态。

### 6.5 法包、位包、律包如何共享

临时判断：

- 共享包必须声明 schema 版本。
- 共享包必须声明适用范围和不适用范围。
- 共享包必须带反例。
- 共享包必须带最小评估集。
- 共享包导入后默认低信，必须经过本地试用才升信。

### 6.6 超大项目中谁拥有上下文预算

临时判断：

- 预算权不属于行者自己。
- 预算权属于业引用的上下文预算律。
- 装境业负责执行预算律并产出上下文包果相。
- 聚合业可以请求扩大预算、插入中间聚合业或派生局部侦察业，但不能私自吞掉遗漏风险。
- 人类愿主只需要裁决高风险遗漏，不应被迫审查所有上下文片段。

## 7. 演进路线

### 7.1 第一阶段：单机最小闭环

目标：

- 相文件可保存。
- 业文件可创建。
- 果必须携证。
- 旧术语、链接、表格、schema 可检查。
- 调试日志、运行日志和质量日志可本地保留。
- 上下文包果相能记录采用项和遗漏项。

不做：

- 多行者复杂协作。
- 联邦共享。
- 自动长期优化。

### 7.2 第二阶段：治理闭环

目标：

- 文件根边界。
- 工具授权。
- 风险累积。
- 高风险暂停。
- 人类裁决镜。
- 审计日志、安全日志可提升为证相或险相。

不做：

- 全自动执行外部副作用。

### 7.3 第三阶段：藏和信

目标：

- 藏候选。
- 藏入库。
- 藏检索。
- 藏过期。
- 行者和法的场景化信用。

不做：

- 假装长期成长一定有效。

### 7.4 第四阶段：递归等级化协作

目标：

- 原子行者处理小业。
- 专业行者处理专业业。
- 聚合业处理跨域果、证、遗漏证和风险。
- 仲裁业处理冲突。
- 超大项目通过地图相、切片相、装境业、聚合业和遗漏证递归生长。

不做：

- 多行者聊天剧场。

### 7.5 第五阶段：可迁移软件社会

目标：

- 法包、位包、律包、业模板、评估包可分享。
- 包导入后低信试运行。
- 不同超级个体之间可以交换可验证果和证。

不做：

- 把别人的经验无条件当成本地真相。

## 8. 当前最小可讨论结论

1. 相和业仍是唯一根结构。
2. 层级只是实现剖面，不是新本体。
3. schema、生命周期、反例必须写进真相源。
4. 更细的运行机制应先在临时稿讨论，成熟后再合并。
5. 藏管理、律权限、文档防污染、风险累积、逐级上报、文件并发、非用户日志系统、递归等级化视野治理，是第一批必须解决的运行机制。
6. 高风险必须逐级上报，更有全局观的行者只能在受律和证管辖下裁决；最高裁决源仍是人类。
7. 文件驱动不是简单把内容写成 Markdown，而是所有相、业、证、律、状态、授权、风险都必须有可迁移文件表达。

## 9. 实现架构蓝图

本章不是新增根概念，而是把“相、业、因、愿、缘、律、位、法、行者、行、果、证、藏、镜、信、险、业网”落到可建设的软件边界。

核心判断：

- 根结构仍只有相和业。
- 所有运行设施都只是相业的管理器、解释器、校验器或投影器。
- 不允许为了某个特殊场景新增根概念。
- 任何设施若不能说清自己持有哪些相、消费哪些相、生成哪些相、受哪些律管辖，就不能进入第一版实现。

### 9.1 总体运行剖面

运行链如下：

1. 人类愿主表达模糊意图、痛点、情绪、设想或反例。
2. 显愿入口把这些材料显影为愿相候选。
3. 业登记器把愿相候选登记为可运行业，并绑定律、位、法、险初值。
4. 装境机按业的需要裁剪相、藏、证、律，形成可承载行的境。
5. 业核驱动行者行事，记录检查点、果相、证相、险相、信相。
6. 治理门、写协调器、证评器、藏库、日志台、镜投影器在业核周围提供治理、写入、评价、沉淀、排障和投影。
7. 愿主或授权行者验收果，决定接收、退回、分解、上报或终止。

这个剖面只表达运行时的责任切面，不表达新的本体层级。每一块都必须以相业文件为最终承载，不允许把真实状态只藏在内存、数据库私有字段或前端状态里。

### 9.3 端到端运行路径

#### 9.3.1 模糊表达到真实愿相

适用场景：愿主只能表达痛点，例如“我觉得现在这个产品很乱，但说不清哪里乱”。

运行路径：

1. 显愿入口收集对话相、情绪相、例子相、反例相。
2. 业登记器建立显愿业，绑定“不得直接给方案”“必须提出可验证反问”“必须区分症状和本愿”等律。
3. 装境机召回类似历史显愿果、相关藏、当前项目地图相。
4. 行者按位和法提出澄清问题、类比、假设、反例。
5. 证评器检查愿相候选是否包含目标、边界、不可接受结果、验收口径。
6. 镜投影器向愿主展示多个愿相候选和差异。
7. 愿主确认后，业登记器把候选固化为本愿相，并生成后续方案业。

预期效果：

- 人不需要一开始就会下完美指令。
- 系统不急于交付，而是先把真实目的显影。
- 后续所有工作都能追溯到本愿相，减少方向漂移。

#### 9.3.2 超大项目到递归等级化协作

适用场景：项目规模超过单一上下文能力，例如百万行工程、跨公司计划、长期科研项目。

运行路径：

1. 相库建立项目地图相，记录目录、文档、模块、接口、已知风险和未知区域。
2. 装境机根据地图相切出多个切片相，每个切片包含局部因相、局部愿相、相关律、邻接边界和遗漏证。
3. 业登记器为每个切片建立局部业，并为上层建立聚合业。
4. 局部行者只处理自己的切片，不假装看见全局。
5. 聚合业只接收局部果、局部证、遗漏证、冲突相和风险相。
6. 若聚合业发现跨切片冲突，则建立仲裁业；若发现上下文仍过大，则继续递归切分。
7. 高位行者只看更抽象的地图相、聚合果和关键风险，不阅读全部细节。

预期效果：

- 工程规模可递归扩展，不依赖固定层数。
- 下层精细，上层全局；每层都承认自己的视野损耗。
- 聚合不是简单摘要，而是带遗漏证和冲突相的有损压缩。

#### 9.3.3 高风险动作到逐级上报

适用场景：删除文件、改安全配置、调用外部付费接口、发布内容、触达真实用户。

运行路径：

1. 行者产生写意图相或工具意图相。
2. 治理门读取律相、险相、信相、工具声明和当前业上下文。
3. 若风险低且在授权范围内，治理门放行并要求留证。
4. 若风险中等，治理门要求生成预览相和回滚相。
5. 若风险高，治理门暂停当前业，生成上报业。
6. 更高位行者审阅愿相、风险相、预览相、回滚相、替代方案相。
7. 若仍无法裁决，则上报愿主。

预期效果：

- 高风险不会因为下层行者“看起来很确定”而直接发生。
- 人类只在价值判断、不可逆动作和风险过高时介入。
- 每次放行、拒绝、上报都有证可查。

#### 9.3.4 文档修改到防污染闭环

适用场景：长期文档被多次修改后产生过时结论、重复定义、术语漂移。

运行路径：

1. 写协调器接收修改候选和基线版本。
2. 相库扫描引用关系、术语关系、被影响章节和相邻文档。
3. 证评器检查候选是否违反根律、是否引入旧名、是否与真相源冲突。
4. 装境机生成影响境，明确采用了哪些章节、遗漏了哪些章节。
5. 行者只在影响境内改文档，不允许凭聊天上下文自由发挥。
6. 写协调器生成预览相，必要时建立冲突业。
7. 评估台运行术语扫描、表格检查、质量审查。
8. 藏库把旧结论降信或标记过期，不让它们继续被召回为高信材料。

预期效果：

- 文档不会因为局部修补留下大量旧幻觉。
- 修改有影响面，不是只改当前段落。
- 旧内容不是被静默遗忘，而是被降信、过期或转入冲突处理。

#### 9.3.5 中断恢复到可继续运行

适用场景：模型调用失败、工具失败、系统重启、上下文过长、人工暂停。

运行路径：

1. 业核在关键状态变化时写检查点。
2. 检查点记录业状态、境版本、已完成行、已生成果、已留证、未决风险。
3. 中断后，业核读取最近可用检查点。
4. 相库校验引用相是否仍存在、版本是否变化。
5. 若版本未变化，业核恢复继续行事。
6. 若版本变化，写协调器建立冲突业或重装境业。
7. 镜投影器向人展示恢复来源、丢失范围和需要裁决的点。

预期效果：

- 长工作不依赖单次会话。
- 中断后不用重新解释全部背景。
- 恢复过程本身也可被审计。

### 9.5 状态机边界

业的状态必须少而硬，防止实现时每个模块私造状态。

| 状态 | 含义 | 允许进入条件 | 允许离开方向 |
|---|---|---|---|
| `draft` | 尚未可行 | 愿相或律缺失 | `ready`、`cancelled` |
| `ready` | 可被调度 | 因、愿、律、位、法齐备 | `running`、`blocked`、`cancelled` |
| `running` | 正在行事 | 已装境且治理门放行 | `paused`、`blocked`、`reviewing`、`failed` |
| `paused` | 主动暂停 | 人工暂停或等待外部材料 | `running`、`cancelled` |
| `blocked` | 被治理门或依赖阻断 | 风险、权限、冲突、缺证 | `running`、`reviewing`、`cancelled` |
| `reviewing` | 等待验收 | 已有果和证 | `accepted`、`rejected`、`running` |
| `accepted` | 果被接收 | 验收通过 | 终态 |
| `rejected` | 果被拒收 | 未满足验收律 | `running`、`cancelled` |
| `failed` | 运行失败 | 工具、模型、文件或治理失败 | `running`、`cancelled` |
| `cancelled` | 被终止 | 愿主或授权行者终止 | 终态 |

### 9.7 日志与相的关系

日志是运行基础设施，不是根概念。

必须区分三类材料：

| 类型 | 用途 | 是否默认进入相库 | 可否影响裁决 |
|---|---|---|---|
| 运行日志 | 排查调用、耗时、错误 | 否 | 只能辅助 |
| 安全日志 | 记录越权、高险、授权链 | 关键项可提升为险相或证相 | 可以 |
| 质量日志 | 记录评估得分、退化、拒收 | 关键项可提升为证相或信相 | 可以 |

提升条件：

1. 与愿相、业相、果相或风险裁决直接相关。
2. 可被哈希、时间、调用链或文件版本校验。
3. 有明确保留期限和可见范围。
4. 不泄露密钥、隐私或无关运行细节。

### 9.8 与最终体验的对应关系

| 用户体验目标 | 需要的实现设施 | 若缺失会发生什么 |
|---|---|---|
| 用户说不清也能开始 | 显愿入口、澄清业、愿相候选、镜投影器 | 系统会直接按表面话执行，方向容易错 |
| 大项目不爆上下文 | 项目地图相、装境机、遗漏证、递归聚合业 | 上下文被塞满，行者凭不完整印象瞎改 |
| 一次尽量做对 | 质量律、证评器、反例相、预览相、拒收相 | 果看似完整，实际不可验收 |
| 高风险不失控 | 治理门、险相、逐级上报、授权相、回滚相 | 低位行者可能做出不可逆伤害 |
| 文档不被污染 | 影响面扫描、术语检查、旧藏降信、冲突业 | 新旧说法共存，后续行者召回旧幻觉 |
| 长工作可恢复 | 检查点、只追加证相事件、相库校验 | 中断后只能靠聊天回忆，容易重复或漏做 |
| 多人多行者协作 | 写协调器、锁、版本、冲突业、聚合业 | 并发覆盖、局部成果无法合并 |
| 人只看关键处 | 镜相、待裁决清单、风险摘要、遗漏证 | 人要么被细节淹没，要么完全失明 |

## 10. 三理论维度评审攻击

本章只做攻击，不替架构辩护。它的目的不是证明方案已经正确，而是找出会导致真实产品失败的结构性漏洞。

### 10.1 系统论攻击：边界、耦合与涌现风险

#### 10.1.1 根概念过强，可能吞掉实现边界

攻击：

- 相和业过于通用，容易把所有东西都归进去，导致工程边界变模糊。
- 如果每个设施都说自己只是“管理相业”，但没有清晰持有状态，就会出现谁都能改、谁都不负责的局面。
- 递归等级化会放大这个问题：上层看到的是聚合果，下层看到的是切片果，中间若无硬边界，错误会在聚合时被包装得更像正确。

需要补强：

- 每个设施必须声明“唯一持有的状态”。
- 每个相必须声明唯一主责设施。
- 任意跨设施修改必须通过业登记器和写协调器。
- 聚合果必须携带遗漏证和冲突相，否则不得被上层接收。

#### 10.1.2 局部最优会伤害整体愿相

攻击：

- 下层行者可能把局部业做得很好，但破坏上层本愿。
- 例如文档术语局部统一，却把未来架构探索空间写死。
- 例如代码局部测试通过，却破坏产品级可迁移目标。

需要补强：

- 每个局部业必须引用上层愿相，而不是只引用局部目标。
- 证评器不能只评局部果，还要评“对上层愿相的贡献或损害”。
- 聚合业必须显式列出局部果之间的张力，不允许只做正向汇总。

#### 10.1.3 人类愿主可能成为瓶颈或单点失效

攻击：

- 架构把最高裁决源放在人类，但复杂系统中人会疲劳、遗漏、误判。
- 如果所有高风险都上报人类，系统会退化为“人类审批地狱”。
- 如果不上报，又可能让低位行者越权。

需要补强：

- 上报必须分级：低险自动留证，中险由高位行者裁决，高险才找愿主。
- 镜投影器只展示需要价值判断、不可逆动作、重大资源投入、方向转折的点。
- 治理门必须支持批量授权、限时授权、范围授权和可撤销授权。

#### 10.1.4 系统会自然产生制度漂移

攻击：

- 律相、法相、位相、藏相会持续增加。
- 若没有清理机制，系统会越来越重，最终每个业都背负大量历史包袱。
- 若清理过猛，又会丢掉关键经验。

需要补强：

- 每个律、法、位、藏都必须有适用范围、来源、有效期和冲突关系。
- 低使用、低信、过期、冲突未解的材料不得默认进入装境。
- 清理本身必须是业，并留下删除理由和可恢复路径。

#### 10.1.5 递归结构可能产生不可见的系统性风险

攻击：

- 递归切分可以支撑超大规模，但也会制造跨层误差。
- 下层遗漏的关键事实可能在上层被压缩掉。
- 上层错误决策会反向污染大量下层业。

需要补强：

- 每次聚合都必须记录压缩损耗。
- 每个上层裁决必须能定位影响到哪些下层业。
- 必须允许下层业反向上报“上层愿相或律相有问题”。

### 10.2 控制论攻击：反馈、稳定与失控风险

#### 10.2.1 反馈太慢会导致大错已成

攻击：

- 如果只在最终验收时检查果，错误已经层层扩散。
- 文档污染、错误代码、错误藏一旦进入后续装境，会被系统当成材料继续使用。

需要补强：

- 关键业必须设置中间验收点。
- 写协调器必须先预览再提交。
- 证评器必须支持小范围试验、反例测试和拒收。
- 藏库不得把未验收果沉淀为高信材料。

#### 10.2.2 反馈太强会导致振荡

攻击：

- 如果每个评估器都能退回，每个治理门都能暂停，系统会在“改、评、退、再改”之间振荡。
- 多个高位行者意见不一致时，可能持续互相推翻。

需要补强：

- 每个业必须有最大返工次数、升级条件和终止条件。
- 仲裁业必须高于普通评审业。
- 对同一争议，不允许无限生成同级争议业。

#### 10.2.3 控制量不清会导致假控制

攻击：

- 质量、风险、信度、进度、成本都被记录，但未必能控制。
- 如果指标只是展示，不参与治理门，就只是仪表盘。

需要补强：

- 每个控制量必须绑定动作：放行、暂停、退回、上报、降信、清理、回滚。
- 每个阈值必须有来源和可调整记录。
- 镜投影器展示的状态必须来自业核、相库、治理门，不能自己推断。

#### 10.2.4 控制者本身也会出错

攻击：

- 证评器可能误判。
- 治理门可能过严或过松。
- 装境机可能漏召回关键相。
- 高位行者可能因为摘要失真做错裁决。

需要补强：

- 控制设施也必须被评估台评估。
- 高风险裁决必须允许独立复核。
- 装境结果必须带采用清单和遗漏证。
- 证评器必须区分“未见问题”和“已证明满足”。

#### 10.2.5 自我优化可能走向错误方向

攻击：

- 系统若按历史成功率调整律、法、藏，可能强化旧路径。
- 愿主认知有限时，自我优化会让系统更会满足旧偏好，而不是扩展能力边界。
- 这与“外骨骼扩展人类”目标冲突。

需要补强：

- 自我优化不得只看满意度，还要看探索收益、反例发现、能力边界扩展。
- 必须保留异见相和反例相。
- 高位探索业可以主动提出“愿主未想到但值得看的方向”，但不得替愿主做最终价值裁决。

### 10.3 信息论攻击：容量、失真与噪声风险

#### 10.3.1 上下文通道容量有限，压缩必然损失

攻击：

- 再好的装境机也无法把大项目全部塞给单次行。
- 摘要、聚合、镜相都是有损压缩。
- 如果文档假装压缩无损，架构会产生系统性假绿。

需要补强：

- 每个境相必须记录预算、采用项、遗漏项和不可判定项。
- 聚合果必须声明压缩口径。
- 高风险业不得只依赖摘要，必须能下钻到原始相和证。

#### 10.3.2 语义编码不一致会制造噪声

攻击：

- 不同位、法、项目、团队对同一术语理解不同。
- “完成”“验收”“风险”“高信”“可迁移”如果没有共同编码，会导致跨层误读。

需要补强：

- 真相源必须维护术语 schema、生命周期和反例。
- 每个项目可有本地术语相，但必须声明与根术语的关系。
- 装境机发现术语冲突时必须生成冲突相，而不是自动选择一个。

#### 10.3.3 藏会引入高信噪声

攻击：

- 旧经验看起来像高价值信息，但可能已经过期。
- AI 修改文档时最容易把旧结论、旧术语、旧方向重新召回。
- 高信但过期的藏比低信材料更危险，因为它更容易被信任。

需要补强：

- 藏必须有适用范围、来源、时间、反例、冲突和有效期。
- 装境必须优先召回新真相源和当前业相关证，再召回藏。
- 被真相源否定的藏必须自动降信或隔离。

#### 10.3.4 证不足会让果不可区分真伪

攻击：

- 文本果很容易“看起来正确”。
- 若没有证，系统无法区分真实完成、模板完成、幻觉完成。
- 多层业传递后，缺证果会被包装成更完整的高层果。

需要补强：

- 关键果必须携证。
- 证必须能说明：采用了什么、改了什么、验证了什么、没覆盖什么。
- 缺证果只能进入待审，不得进入高信藏。

#### 10.3.5 信息安全与隐私会限制共享

攻击：

- 架构强调可迁移、可分享，但真实项目有密钥、隐私、商业秘密。
- 如果相、证、藏、日志边界不清，共享会泄露敏感材料。
- 如果过度脱敏，又会损失验证价值。

需要补强：

- 相库必须支持可见范围、脱敏版本和共享版本。
- 日志提升为相前必须经过脱敏。
- 可迁移包必须声明依赖、缺失、脱敏程度和不可验证部分。

### 10.4 三维度共同指出的最大漏洞

| 漏洞 | 系统论视角 | 控制论视角 | 信息论视角 | 当前应对 |
|---|---|---|---|---|
| 假完成 | 局部果冒充整体完成 | 验收反馈太晚 | 缺证无法判真伪 | 证评器、质量律、拒收相 |
| 上下文失真 | 层级压缩造成整体误判 | 高位裁决基于失真视图 | 通道容量不足 | 境相、遗漏证、下钻机制 |
| 文档污染 | 旧相继续影响新业 | 反馈滞后导致污染扩散 | 高信噪声污染藏 | 影响面扫描、降信、冲突业 |
| 治理失控 | 人类成为瓶颈或被绕过 | 控制阈值过严或过松 | 风险信息不完整 | 治理门、逐级上报、授权相 |
| 递归误差 | 多层聚合放大局部偏差 | 上层错误反向扩散 | 有损摘要不可见 | 聚合证、压缩损耗、反向上报 |
| 自我优化偏航 | 系统强化旧路径 | 指标诱导错误行为 | 历史样本偏置 | 异见相、探索业、反例相 |

### 10.5 当前临时方案还不够硬的地方

1. 设施命名已经较清楚，但每个设施的持久化 schema 仍需更细。
2. 质量律还没有形成可执行的最小表达，需要定义评分、拒收、补证和反例接口。
3. 装境机是整个架构成败关键，但当前只定义了职责，未定义召回、裁剪、排序、遗漏记录的硬算法边界。
4. 治理门需要风险累积公式，否则“逐级上报”会变成人工感觉。
5. 藏库必须先有污染隔离和降信机制，再谈长期成长。
6. 镜投影器必须避免美化系统状态，尤其不能把未验收、缺证、待裁决的业展示成接近完成。
7. 递归等级化需要强制反向上报通道，否则上层错误会压死下层真实发现。

### 10.6 下一步应优先定稿的实现顺序

1. 相库、业登记器、业状态机：没有它们，一切都是文本设想。
2. 装境机最小版：必须解决上下文爆炸和遗漏显式化。
3. 治理门和写协调器：先防止不可逆伤害。
4. 证评器和质量律：先解决假完成。
5. 藏库低信版：只允许沉淀候选，暂不允许自动影响高风险业。
6. 镜投影器：把真实状态给人看，而不是做漂亮面板。
7. 评估台：用反例持续打击架构自信。
