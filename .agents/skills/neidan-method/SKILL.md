# 内丹法

这不是一个给通用 Codex 自动轻触发的轻量技能，而是 Jingu 的方法原型。它的用途是主动把模糊愿望推成可执行能力闭环，并在反复使用、反馈、修正中逐步内化为“法”。

内丹法的目标不是只想明白，而是把“我想要但我不会做”转成一条能执行、能验收、能修正、能沉淀的路径。

## 总循环

```text
原始愿望
  -> 复用扫描
  -> 思路地图
  -> 任务业
  -> 概念拆解
  -> 递归下钻
  -> 原子动作层
  -> 可执行标准
  -> 事实 / 假设 / 推论 / 逻辑链条
  -> 证据 / 范例 / 反例
  -> 临时法
  -> 完整产物
  -> 临时法自验收
  -> 外部反馈 / 评价
  -> 法更新或回退
```

## 概念边界

- `层`：一次内丹法执行内部的递归下钻深度。把一个概念继续拆到机制、动作、信号、失败信号、边界和验收，属于“层”，不等于“轮”。
- `轮`：一次完整闭环。必须包含重新读取原始愿望、完整拆解、定义、量化、执行、输出完整产物、验收、反馈、修正方法、再回到原始愿望。缺任一项都不能叫一轮。
- `控制论负反馈`：用于训练、评测和收敛内丹法的外部程序，不是内丹法本体。不要把负反馈评测流程写成内丹法步骤。

详细边界见 `references/concept-boundaries.md`。当任务涉及“多轮”“迭代”“评测”“收敛方法”时，必须先读 `references/control-feedback-cycle.md`。

## 核心纪律

1. 先保存原始愿望，再改写为任务结构。
2. 先做复用扫描，再决定是否新拆解。优先复用当前真相、已有法、本地技能、可参考外部技能或文档，能改造就不要重造。
3. 任何不明白的概念都不能跳过。先自行查询、读取可用资料或上网核验；若仍不清楚，明确反问。不得用熟悉词汇掩盖不理解。
4. 给出方案前必须先整理思路地图，标清前后背景、目标、关键概念、依赖、冲突、风险和未知项。
5. 所有结论都必须有 `事实`、`假设`、`推论`、`逻辑链条` 四类支撑；缺任一类时只能标为待证，不得伪装成结论。
6. 必须保持诚实。即使结论会让执行者或愿主不舒服，也要如实指出风险、问题、冲突、不确定性和可能失败处。
7. 不因为产物容易做就缩小最终目标。必须同时保留最终目标、当前阶段产物和验证对象。
8. 概念不能只拆一层。每个关键概念都要继续下钻到机制、动作、信号、失败信号、边界和验收。
9. 只有能改善执行、验收、风险控制或价值判断的子业才值得建立，避免装饰性拆分。
10. 低层执行细节优先由系统给默认方案；只有当答案会实质改变方向、风险、价值取舍或不可逆承诺时才问人。
11. 社区经验、专家经验、测试、市场数据、物理反馈、人类反馈和 AI 评审都可以用，但可靠性不同，必须标明来源等级。
12. 临时法必须可执行、可观察、可量化验收。抽象口号、价值宣言、比喻句不能冒充法。
13. 任何临时法都必须可被反馈推翻、修正或废弃。
14. 需要人判断、测试或作为证据的产物必须完整输出。不得用节选、概要、省略号、片段、示例段落替代真实交付；内容过大时拆分为多个文件或多个部分，但不得降低完整度。

## 认知诚实约束

执行内丹法时必须显式记录：

```text
事实: 已知为真或由可靠来源直接支持的内容。
假设: 当前为了推进而暂时采用、但可能被推翻的内容。
推论: 从事实和假设推出的判断。
逻辑链条: 从事实/假设到推论再到行动方案的因果路径。
未知项: 当前仍不清楚、需要查询、测试或询问的内容。
风险/冲突: 可能造成失败、误判、返工、价值冲突或安全问题的内容。
```

如果关键概念不清楚：

1. 先查本地真相、已有法、技能、仓库材料。
2. 本地材料不足时，上网查询可信来源并标注来源等级。
3. 仍不足时，提出最小必要反问。
4. 查询或反问前可以给临时假设，但必须标为假设，不得当成事实。

## 工作流程

### 1. 建立任务业

先写清任务契约：

```
原始愿望:
最终目标:
当前阶段产物:
验收对象:
非目标:
已知约束:
风险等级:
反馈渠道:
```

如果用户给的是大目标，不能让一个小样稿冒充最终交付。

### 1.5 复用扫描

在更深拆解前，先盘点可复用项：

- 当前真相和已建立的法
- 仓库内现有技能和参考资料
- 可信的外部技能、文档或模板

每个候选项都要标注：

- 直接复用
- 改造复用
- 仅作参考
- 忽略

这个阶段要限时。目标是避免重复造轮子，不是无限搜索。

### 1.6 思路地图

在给方案、临时法或产物前，必须先形成可读的思路地图：

```
背景:
目标:
关键概念:
已知事实:
关键假设:
推论:
逻辑链条:
未知项:
风险/冲突:
需要查询或反问:
```

思路地图不是长篇解释，而是让后续每个动作有来源、边界和可追踪依据。

### 2. 概念拆解

列出愿望里的关键概念。每个概念都要标注：

```
概念:
角色: 目标 | 材料 | 质量 | 约束 | 风险 | 受众 | 工具 | 领域
当前清晰度: 清晰 | 模糊 | 冲突 | 缺失
是否阻塞执行: 是 | 否
是否阻塞验收: 是 | 否
是否需要外部证据: 是 | 否
是否需要人类决策: 是 | 否
事实依据:
当前假设:
可被推翻的条件:
```

### 3. 递归下钻

不要停在第一层名词解释。每个阻塞概念至少继续追问到下面几个层次：

- 机制：它是怎么产生的？
- 结构：它由哪些部件组成？
- 动作：要做哪些可执行动作才会出现？
- 信号：出现了什么才算它真的成立？
- 失败信号：什么表现说明它不成立？
- 边界：什么情况下它不适用？
- 反馈源：靠什么外部或内部反馈修正它？

如果一个概念还不能落到动作或信号，就说明还没下钻够。

### 4. 原子动作层

每个叶子节点都要尽量映射到原子动作。常见原子动作包括：

- 检索
- 比较
- 归纳
- 选择
- 生成
- 修改
- 校验
- 发布
- 记录
- 转译
- 反馈
- 回退

不能执行、不能观察、不能校验的概念，不算真正拆完。

### 5. 生成临时法

把当前任务需要的法写成可执行对象：

禁止把抽象句写成临时法。例如：

```text
无效: 业为日志锚定目标，使其不散。
有效: 每个运行轮次必须生成 root_job_id；每条候选、证据、反馈事件必须带 job_id/root_job_id；验收时抽样 100% 事件，若缺任一必需 id 则失败。
```

临时法必须写到可被执行者照做的粒度：

```
法名:
适用范围:
步骤:
  - 动作:
    输入:
    执行者/工具:
    输出:
    可观察信号:
    量化验收标准:
    失败信号:
    回退/修正规则:
规则:
原子动作:
示例:
反例:
质量检查:
  - 检查项:
    通过标准:
    证据:
    未通过处理:
需要收集的反馈:
修正规则:
```

临时法必须能被另一位人或另一位执行者独立读懂并执行，不能只对当前上下文有意义。每个步骤至少要有一个可观察信号和一个量化验收标准；无法量化时必须说明为什么不能量化，并给出可替代的观察标准。

### 6. 执行产物

不是只分析。必须拿临时法产出当前阶段最好的完整对象。

大型任务至少要产出：

- 最终目标图
- 当前阶段交付物
- 下一批执行计划
- 哪些反馈会推动法更新

### 7. 用法自验收

临时法生成后，必须用它自己验一次产物：

```text
1. 这份产物是否真的满足任务契约？
2. 每个关键概念是否已经落到动作、信号或边界？
3. 这份法是否真的指导了执行，而不是只做了总结？
4. 哪些地方仍然只能靠外部反馈决定？
5. 每个临时法步骤是否都有输入、动作、输出、执行者、可观察信号、量化验收标准和失败处理？
6. 每个验收结论是否都有事实、假设、推论和逻辑链条支撑？
```

如果临时法连自己都验不过，就不能假装成熟。

验收结果必须用表格或清单呈现：

```text
检查项:
标准:
实际证据:
结论: 通过 | 未通过 | 待证
缺口:
修正动作:
```

### 8. 外部反馈与更新

可用反馈包括：

```text
人类反馈
物理测试
单元/集成测试
市场数据
专家/社区经验
AI 评审
来源比对
红队审查
```

记录：

```
已确认:
已削弱:
已变化:
新缺口:
法更新:
需要回退:
```

## 输出形态

除非任务另有要求，默认按这个结构输出：

```text
原始愿望:
任务业:
复用扫描:
思路地图:
事实 / 假设 / 推论 / 逻辑链条:
概念图:
下钻层:
阻塞缺口:
子业:
临时法:
原子动作:
量化验收表:
完整产物:
验收结果:
风险 / 冲突 / 未知项:
法更新说明:
观察到的失败模式:
```

## 失败模式

- 目标坍缩：把用户最终目标缩成一个容易交付的小样。
- 单层拆解：只拆第一层概念，没有继续下钻到机制、动作和验收。
- 概念装饰：拆了一堆词，但没有改善执行。
- 伪量化：只给模糊标签，没有可执行标准。
- 来源扁平化：把论坛经验、专家规则、基准测试和物理反馈当成同一层证据。
- 追问泛滥：把低层细节也丢给人问，系统不提出默认方案。
- 自封闭方法：生成一个不能被反馈修正的法。
- 上下文膨胀：把全部子业过程都塞回父业，而不是只回传结论、证据和开放问题。
- 不验收：产出法之后没有反过来验产物。
- 轮层混淆：把一次闭环中的多层下钻误称为多轮迭代。
- 节选冒充交付：用片段、摘要或“略”代替需要用户判断的完整产物。
- 抽象法冒充临时法：用“锚定目标”“保持一致”“提升质量”等抽象句替代可执行步骤。
- 无量化验收：只有“满足”“有效”“清晰”等判断，没有标准、证据和通过/失败条件。
- 结论无支撑：给出结论但没有事实、假设、推论和逻辑链条。
- 风险遮蔽：为了让产物显得顺利而忽略风险、冲突、未知项或不舒服的事实。

出现任一失败模式时，必须先指出，再修法继续。
