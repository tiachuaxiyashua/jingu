# 内丹法

这不是一个给通用 Codex 自动轻触发的轻量技能，而是 Jingu 的方法原型。它的用途是主动把模糊愿望推成可执行能力闭环，并在反复使用、反馈、修正中逐步内化为“法”。

内丹法的目标不是只想明白，而是把“我想要但我不会做”转成一条能执行、能验收、能修正、能沉淀的路径。

## 总循环

```text
原始愿望
  -> 复用扫描
  -> 任务业
  -> 概念拆解
  -> 递归下钻
  -> 原子动作层
  -> 可执行标准
  -> 证据 / 范例 / 反例
  -> 临时法
  -> 完整产物
  -> 临时法自验收
  -> 外部反馈 / 评价
  -> 法更新或回退
```

## 概念边界

- `层`：一次内丹法执行内部的递归下钻深度。把一个概念继续拆到机制、动作、信号、失败信号、边界和验收，属于“层”，不等于“轮”。
- `轮`：一次完整闭环。必须包含重新读取原始愿望、完整拆解、定义、量化、执行、输出完整产物、验收、反馈、修正方法、再回到原始愿望。缺任一项都不能叫一轮。
- `控制论负反馈`：用于训练、评测和收敛内丹法的外部程序，不是内丹法本体。不要把负反馈评测流程写成内丹法步骤。

详细边界见 `references/concept-boundaries.md`。当任务涉及“多轮”“迭代”“评测”“收敛方法”时，必须先读 `references/control-feedback-cycle.md`。

## 核心纪律

1. 先保存原始愿望，再改写为任务结构。
2. 先做复用扫描，再决定是否新拆解。优先复用当前真相、已有法、本地技能、可参考外部技能或文档，能改造就不要重造。
3. 不因为产物容易做就缩小最终目标。必须同时保留最终目标、当前阶段产物和验证对象。
4. 概念不能只拆一层。每个关键概念都要继续下钻到机制、动作、信号、边界和验收。
5. 只有能改善执行、验收、风险控制或价值判断的子业才值得建立，避免装饰性拆分。
6. 低层执行细节优先由系统给默认方案；只有当答案会实质改变方向、风险、价值取舍或不可逆承诺时才问人。
7. 社区经验、专家经验、测试、市场数据、物理反馈、人类反馈和 AI 评审都可以用，但可靠性不同，必须标明来源等级。
8. 任何临时法都必须可被反馈推翻、修正或废弃。
9. 需要人判断、测试或作为证据的产物必须完整输出。不得用节选、概要、省略号、片段、示例段落替代真实交付；内容过大时拆分为多个文件或多个部分，但不得降低完整度。

## 工作流程

### 1. 建立任务业

先写清任务契约：

```
原始愿望:
最终目标:
当前阶段产物:
验收对象:
非目标:
已知约束:
风险等级:
反馈渠道:
```

如果用户给的是大目标，不能让一个小样稿冒充最终交付。

### 1.5 复用扫描

在更深拆解前，先盘点可复用项：

- 当前真相和已建立的法
- 仓库内现有技能和参考资料
- 可信的外部技能、文档或模板

每个候选项都要标注：

- 直接复用
- 改造复用
- 仅作参考
- 忽略

这个阶段要限时。目标是避免重复造轮子，不是无限搜索。

### 2. 概念拆解

列出愿望里的关键概念。每个概念都要标注：

```
概念:
角色: 目标 | 材料 | 质量 | 约束 | 风险 | 受众 | 工具 | 领域
当前清晰度: 清晰 | 模糊 | 冲突 | 缺失
是否阻塞执行: 是 | 否
是否阻塞验收: 是 | 否
是否需要外部证据: 是 | 否
是否需要人类决策: 是 | 否
```

### 3. 递归下钻

不要停在第一层名词解释。每个阻塞概念至少继续追问到下面几个层次：

- 机制：它是怎么产生的？
- 结构：它由哪些部件组成？
- 动作：要做哪些可执行动作才会出现？
- 信号：出现了什么才算它真的成立？
- 失败信号：什么表现说明它不成立？
- 边界：什么情况下它不适用？
- 反馈源：靠什么外部或内部反馈修正它？

如果一个概念还不能落到动作或信号，就说明还没下钻够。

### 4. 原子动作层

每个叶子节点都要尽量映射到原子动作。常见原子动作包括：

- 检索
- 比较
- 归纳
- 选择
- 生成
- 修改
- 校验
- 发布
- 记录
- 转译
- 反馈
- 回退

不能执行、不能观察、不能校验的概念，不算真正拆完。

### 5. 生成临时法

把当前任务需要的法写成可执行对象：

```
法名:
适用范围:
步骤:
规则:
原子动作:
示例:
反例:
质量检查:
需要收集的反馈:
修正规则:
```

临时法必须能被另一位人或另一位执行者独立读懂并执行，不能只对当前上下文有意义。

### 6. 执行产物

不是只分析。必须拿临时法产出当前阶段最好的完整对象。

大型任务至少要产出：

- 最终目标图
- 当前阶段交付物
- 下一批执行计划
- 哪些反馈会推动法更新

### 7. 用法自验收

临时法生成后，必须用它自己验一次产物：

```text
1. 这份产物是否真的满足任务契约？
2. 每个关键概念是否已经落到动作、信号或边界？
3. 这份法是否真的指导了执行，而不是只做了总结？
4. 哪些地方仍然只能靠外部反馈决定？
```

如果临时法连自己都验不过，就不能假装成熟。

### 8. 外部反馈与更新

可用反馈包括：

```text
人类反馈
物理测试
单元/集成测试
市场数据
专家/社区经验
AI 评审
来源比对
红队审查
```

记录：

```
已确认:
已削弱:
已变化:
新缺口:
法更新:
需要回退:
```

## 输出形态

除非任务另有要求，默认按这个结构输出：

```text
原始愿望:
任务业:
复用扫描:
概念图:
下钻层:
阻塞缺口:
子业:
临时法:
原子动作:
完整产物:
验收结果:
法更新说明:
观察到的失败模式:
```

## 失败模式

- 目标坍缩：把用户最终目标缩成一个容易交付的小样。
- 单层拆解：只拆第一层概念，没有继续下钻到机制、动作和验收。
- 概念装饰：拆了一堆词，但没有改善执行。
- 伪量化：只给模糊标签，没有可执行标准。
- 来源扁平化：把论坛经验、专家规则、基准测试和物理反馈当成同一层证据。
- 追问泛滥：把低层细节也丢给人问，系统不提出默认方案。
- 自封闭方法：生成一个不能被反馈修正的法。
- 上下文膨胀：把全部子业过程都塞回父业，而不是只回传结论、证据和开放问题。
- 不验收：产出法之后没有反过来验产物。
- 轮层混淆：把一次闭环中的多层下钻误称为多轮迭代。
- 节选冒充交付：用片段、摘要或“略”代替需要用户判断的完整产物。

出现任一失败模式时，必须先指出，再修法继续。
