## Context

当前 AI 沙盒具备根业执行、分业申请登记、子业法调用帧和候选校验能力。缺口是登记后的子业不会被调度，因此业树不会通过前沿执行产生果包和下一层阻塞点。

真相源要求“执行上：业树引擎可以按阻塞前沿调度当前活跃子业，但不能丢失父子层级”。本变更实现最小可验证调度，不做完整并行调度器。

## Goals / Non-Goals

**Goals:**

- 在根业自动分业登记后，调度当前活跃前沿子业执行一次。
- 子业用自己的 method 调用帧执行；没有子业 method 时使用根业 method 作为退化。
- 子业只提交结构化果包候选与证据，不自动接受、不宣告父业完成。
- 子业执行后记录父业重评估数据，便于日志分析。
- 子业候选也可触发一层新的分业申请登记，使业树能继续生长出孙业。

**Non-Goals:**

- 不实现无限递归调度。
- 不并行执行子业。
- 不自动接收子业候选果包。
- 不根据小说、人物或某个具体任务写死拆分策略。
- 不把父业重评估结果当作完成裁决。

## Decisions

1. **调度活跃前沿叶子业。**

   使用 `TreeService.get_frontier(root_job_id)` 读取活跃叶子业，只调度父业不是空的子业，避免重复执行根业。第一版限制每轮最多调度少量前沿业，防止模型调用爆炸。

2. **子业响应必须是果包 JSON。**

   子业 provider 请求要求输出 `conclusion`、`artifacts`、`evidence_summary`、`open_questions`、`suggested_follow_up_jobs`。提交走 `TreeService.submit_result_package`，复用已有结构校验。

3. **子业 method 从调用帧读取。**

   若子业已有 `method_call_frames`，读取最后一条的 `method_path` 并加载对应 method；否则使用当前根 method。这样不需要在代码中硬编码 PDCA、辩证法等名称。

4. **父业重评估只记录，不裁决。**

   每个子业提交果包后调用 `TreeService.reevaluate_parent(parent_job_id)`，把结果写入日志。由于果包只是候选，父业通常仍显示存在未解决子业，这是符合候选隔离律的。

5. **子业可提出下一层分业，但不在同一轮继续执行孙业。**

   子业果包候选之后调用既有 `run_split_proposal_registration()`，让孙业能登记出来。第一版停止在登记层，防止无限递归和成本失控。

## Risks / Trade-offs

- [风险] 子业果包不是 accepted，父业重评估仍显示未完成。→ 这是正确的候选隔离；后续需要独立验收位或人类裁决来接收。
- [风险] 子业执行增加 provider 调用次数。→ 第一版设置小的调度上限，并记录跳过/结束原因。
- [风险] 模型不输出合法果包 JSON。→ 记录拒绝，不创建候选果包，不影响根业主链路。
- [风险] method 调用帧缺失或路径失效。→ 退化到根 method 或记录加载失败，避免静默错误。
