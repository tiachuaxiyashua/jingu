## Context

`truth/00-当前真相源-人工智能软件社会相业架构.md` 明确要求：需要调用法的业应有自己的法绑定字段；任意法嵌套调用其他法时，每次调用都必须形成法调用帧；复杂任务需要真实业树，子业供料证成，不能宣告父业完成。

当前代码已经具备三块基础：

- `RuntimeService.create_child_job()` 和 `TreeService.propose_child_job()` 能创建真实父子业。
- `load_method_context()` 能把一个 method 文件拆成法片段。
- `RuntimeService.bind_method_law_fragments()` 能把法片段作为相绑定到当前业。

缺口是：法绑定还停留在“当前业绑定片段”，没有独立的法调用帧；`tree propose-child` 也不能在创建子业时把法绑定到子业。因此多法套用容易退化为同一个业的一次大 prompt，而不是父业拆分、子业调用、果包回流。

## Goals / Non-Goals

**Goals:**

- 让子业提议可以携带可选法绑定，并把该法绑定记录在子业上。
- 为每次法绑定记录法调用帧，包含输入、输出契约、验收标准、回流点、预算、深度和重复检测键。
- 让树视图和父业重评估能看到每个子业的法调用帧，方便人工从日志和 CLI 判断业树是否按预期生长。
- 新增 PDCA、控制变量法、辩证法三个独立法相，支持手动验证“父业内丹法拆解，子业按阻塞点调用其他法”。

**Non-Goals:**

- 不实现同一个 method 文件的 `includes`、静态多法合并或组合加载器。
- 不让 AI 沙盒自动执行任意多层子业调度；本次只补运行库和 CLI 的真实承载能力。
- 不把 PDCA、控制变量法或辩证法写死进引擎分支。它们只是可加载文件。
- 不让子业结果自动成为父业完成声明；仍通过候选、证据、果包和父业重评估回流。

## Decisions

1. **法调用帧先用事件承载，不新增表。**

   真相源允许第一版把语义对象压缩在核心表和事件里。调用帧目前只需要审计、日志和树视图，不需要独立查询权限或高并发写入，因此用 `method_call_frame_opened` 事件记录。若后续查询、权限或迁移压力出现，再提升为表。

2. **子业法绑定由 proposal 数据驱动。**

   `TreeService.propose_child_job()` 增加可选 method 参数。若用户或上层 AI 提案提供 method 路径和绑定原因，则创建子业后把该 method 绑定到子业，并打开调用帧。若没有提供 method，则照旧创建无绑定子业。

3. **调用帧引用已存在的提议字段，不自造任务语义。**

   调用输入来自父业编号、子业目标、阻塞原因和上下文缺口；输出契约和验收标准来自子业提议；预算来自估算努力和深度限制；回流点必须由调用方提供。这样避免“系统替用户编造法调用理由”。

4. **树视图读取事件投影，而不是复制状态。**

   `tree show` 和 `reevaluate` 从事件账本投影 `method_call_frames`，不在 `jobs` 表新增重复字段。这样保留事件只追加原则。

5. **AI 沙盒根业也记录调用帧，但仍只绑定一个 method。**

   对 `ai run/chat --method`，根业绑定 method 时记录一条调用帧，说明当前根业调用了哪个法。它不代表多法组合；多法验证必须在真实子业上继续发生。

## Risks / Trade-offs

- [风险] 事件投影查询比表字段慢。→ 当前最小系统数据量很小，优先保持模型简单；后续有查询压力再提升为表。
- [风险] CLI 增加 method 参数后用户可能误以为系统会自动跑完子业。→ 文档、任务和输出中明确本次是“承载和显影能力”，不是自动调度器。
- [风险] 子业 method 绑定失败会让创建流程复杂。→ 先解析 method 文件，再创建子业；解析失败不创建子业。
- [风险] 法调用帧字段太少无法支持未来复杂预算。→ 使用结构化 JSON payload，保留扩展空间。
